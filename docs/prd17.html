이 PRD는 해커톤 주최 측 요청에 따라 개발을 진행하던 중에 작성했습니다. 그동안의 아이디어 메모, 질문 6라운드로 정한 결정, Spec v1~v6, 환류 기록 7건, 실제 공문 시험 결과를 하나로 정리한 문서입니다.

1. 개요

똑공다는 초등학교 선생님이 업무관리시스템에서 내려받아 PC의 날짜 폴더에 넣어 둔 공문을 클로드(AI)가 읽고 정리해 주는 PC 앱입니다. 공문을 보고·일정·안내로 나누고, 공문 속 마감일·행사일·신청 기간을 첫 화면의 달력에 모아 줍니다. 보고 공문에서는 붙임 서식(hwpx)의 모양을 그대로 살린 보고서 초안을 만들어 줍니다. 원본 공문 파일은 절대 바꾸지 않으며, 개인정보가 보이는 파일은 클로드로 보내기 전에 선생님이 직접 고릅니다.

2. 문제 정의

  • 누가: 공문을 받아 처리하는 초등학교 선생님(특히 공문이 몰리는 교무·업무 담당 교사)
  • 어떤 상황에서: 업무관리시스템에서 공문의 본문(PDF)과 붙임(한글·엑셀·PDF)을 내려받아 PC에 모아 둘 때
  • 어떤 문제를:
    1. 하나하나 열어 봐야 보고(제출) 공문인지, 날짜만 챙기면 되는 일정 공문인지, 읽고 끝나는 안내 공문인지 알 수 있다.
    2. 마감일·연수일·신청 기간이 여러 공문에 흩어져 있어 놓치기 쉽다.
    3. 보고 공문마다 붙임 서식을 열어 학교명·학교장·현황 같은 같은 내용을 처음부터 다시 채운다.
  • 근거:
    • 기획자(현직 교무부장)의 업무 경험과 아이디어 메모(docs/idea.md)
    • 실제 공문 시험(2026-11-21): 해커톤 공문 1건에 행사일 4번·수강신청 마감 1번이 섞여 있었고, 구례교육지원청 연구학교 공모 공문 1건의 붙임에는 제출 서식 4개(학교 현황, 응모 동의서, 준수 확인서, 겉표지)가 한 파일에 들어 있었다.
    • 실제 공문 파일 이름 모양이 두 가지였다: … [토지초등학교-4152 (본문)].pdf, (토지초등학교-4323 (첨부) 구례교육지원청 교육지원과) ….hwpx. 같은 공문의 본문과 붙임을 사람이 이름을 보고 짝지어야 한다.
    • ※ 선생님 여러 명을 대상으로 한 설문·인터뷰 자료는 아직 없습니다(16장 미결 사항).

3. 목표와 비목표

목표

  • 날짜 폴더에 공문을 넣고 '새 공문 정리'를 누르기만 하면, 공문이 종류별로 정리되고 날짜가 달력에 모인다.
  • 달력에서 날짜를 누르면 그날 공문을 바로 확인하고, 그 자리에서 보고서 초안(텍스트 또는 한글 서식)을 만든다.
  • 원본 공문 파일은 읽기만 하고, 초안은 언제나 새 파일로 저장한다.
  • 클로드로 보내기 전에 개인정보가 보이는 파일을 알려 주고 선생님이 보낼지 고른다.
  • 클로드가 모르는 학교 고유 값(학생 수, 동의 결과, 서명 등)은 지어내지 않고 '직접 채울 칸'으로 남긴다.

비목표

  • 업무관리시스템에서 공문을 자동으로 내려받기 (사람이 날짜 폴더에 넣는다)
  • 구글 캘린더 연동 (지금은 앱 안의 달력만)
  • 여러 선생님 공유 (시제품은 개인 사용자 한 명용)
  • 웹 서비스 배포, 설치 파일(exe) (시제품은 PC에서 파이썬으로 실행)
  • .hwp 파일로 초안 만들기 (hwpx만 지원, .hwp 붙임은 hwpx로 다시 저장하도록 안내)
  • 클로드가 결재·제출까지 대신하기

6. 사용자 스토리

US-1: 공문함 읽고 한 공문으로 묶기

선생님으로서, 날짜 폴더에 공문을 넣기만 하면 똑공다가 찾아 주기를 원한다. 따로 등록하는 수고를 덜기 위해서다.

수용 기준:

  • 같은 문서번호의 본문과 붙임이 한 공문으로 묶인다(이름 끝 대괄호 모양, 이름 앞 괄호 모양 모두).
  • 문서번호가 없는 파일은 파일 하나가 공문 하나가 된다.
  • '초안' 폴더 안의 파일은 공문으로 잡히지 않는다.
  • 정리 전후로 원본 파일의 지문이 같다.

US-2: 새 공문만 정리하기

선생님으로서, '새 공문 정리'를 누르면 아직 정리하지 않은 공문만 처리되기를 원한다. 같은 공문에 요금이 두 번 나가지 않게 하기 위해서다.

수용 기준:

  • 공문마다 종류(보고/일정/안내), 제목, 보낸 기관, 한 줄 요약, 날짜와 근거 문장을 저장한다.
  • 두 번 눌러도 이미 정리한 공문은 다시 보내지 않는다.
  • 앱을 다시 켜도 정리 결과가 남는다.

US-3: 개인정보 알림

선생님으로서, 클로드로 보내기 전에 개인정보가 보이는 파일을 알고 보낼지 고르고 싶다. 개인정보가 모르게 나가지 않게 하기 위해서다.

수용 기준:

  • 이름(성명) 칸·명단, 휴대전화 번호, 주민등록번호 형식, 생년월일 칸이 있으면 파일별 이유와 함께 알린다.
  • 기본값은 '보내지 않기'이고, 보내지 않은 파일은 정리에 쓰이지 않지만 목록에는 남는다.
  • 글자를 읽지 못한 파일은 '확인하지 못했어요'로 알린다.

US-4: 첫 화면 달력

선생님으로서, 앱을 열면 한 달의 마감일·행사일·신청 기간을 달력으로 보고 싶다. 이번 달 일정을 한눈에 계획하기 위해서다.

수용 기준:

  • 마감일(빨강), 행사일(파랑), 신청 기간(파란 빗금)을 구분하고, 여러 날 행사는 이어진 막대로 보인다.
  • 막대에는 공문 제목이 아닌 날짜별 짧은 이름이 보인다(예: '해커톤 1차 집합연수').
  • 실제로 모이는 날만 행사일로 넣고, 여러 회차를 감싸는 '운영 기간'은 넣지 않는다.
  • 날짜가 애매한 공문은 달력에 넣지 않고 '날짜 확인 필요'로 따로 보인다.

US-5: 날짜 클릭 → 자세히 보기

선생님으로서, 달력의 날짜를 누르면 그날 공문을 보고 하나를 골라 자세히 보고 싶다. 그날 할 일을 모아 확인하기 위해서다.

수용 기준:

  • 그날 공문이 하나면 바로 자세히 보기, 여러 개면 그날 공문 목록이 뜬다.
  • 자세히 보기에 날짜와 근거 문장, 파일 목록(누르면 PC 기본 프로그램으로 열림)이 나온다.

US-6: 할 일 목록과 제출 완료

선생님으로서, 달력 옆 할 일 목록에서 남은 날과 끝낸 일을 구분하고 싶다. 급한 일부터 처리하기 위해서다.

수용 기준:

  • 'D-3', '오늘 마감', 'n일 지남'이 보이고, 종류별 걸러 보기와 마감일 순 정렬이 된다.
  • 제출 완료한 공문도 날짜 순서 제자리에 남고 빨간 가운데 줄로 표시된다(목록·달력 모두).

US-7: 우리 학교 해당 표시

선생님으로서, 명단에 우리 학교 선생님이 있으면 표시되기를 원한다. 우리 학교가 해당하는 공문을 놓치지 않기 위해서다.

수용 기준:

  • 본문·붙임(명단 포함)에서 우리 학교 소속 사람을 찾아 이름·이유·찾은 파일을 보여 준다.
  • 서식의 '예시' 행 사람은 넣지 않는다.

US-8: 텍스트 초안

선생님으로서, 보고 공문에서 버튼 하나로 복사해 쓸 수 있는 초안을 받고 싶다. 서식을 채우는 시간을 줄이기 위해서다.

수용 기준:

  • 제출 공문(시행문), 서식별 채울 내용, 계획서 뼈대, 제출 체크리스트를 담는다.
  • 학교 고유 값은 【직접 입력: …】/【직접 선택: …】으로 남기고, 직접 채울 칸 목록을 보여 준다.
  • 날짜 폴더의 '초안' 폴더에 새 파일로 저장되고, 다시 만들어도 덮어쓰지 않는다.

US-9: 한글 서식 초안

선생님으로서, 붙임 한글 서식의 표·글꼴·여백을 그대로 지킨 초안 파일을 받고 싶다. 서식을 다시 맞추는 수고를 덜기 위해서다.

수용 기준:

  • 붙임 hwpx를 복사해 칸만 채운 새 hwpx를 만든다(원본 그대로).
  • 학교 기본 정보(주소, 전화, 학교장명 등)를 한 번 저장해 두면 알맞은 칸에 채운다.
  • 칸보다 긴 글은 "‘토지초등학교장’(7글자, 칸은 약 6글자)"처럼 쉬운 말로 알린다.
  • 한글 프로그램에서 쪽수·줄바꿈이 유지되는지 선생님 확인(미완료)

US-10: 직접 고침과 다시 정리

선생님으로서, 클로드가 잘못 정리한 종류·날짜를 직접 고치고, 다시 정리해도 내가 고친 값이 모르게 바뀌지 않기를 원한다.

수용 기준:

  • 종류와 날짜를 고치거나 더하거나 뺄 수 있고 '직접 고침' 표시가 붙는다.
  • 다시 정리한 값이 직접 고친 값과 다르면 두 값을 나란히 보여 주고 고른 값만 남긴다.

US-11: 진행 상황과 실패 처리

선생님으로서, 정리 중 진행 상황을 보고, 하나가 실패해도 나머지는 정리되기를 원한다.

수용 기준:

  • '4건 중 2건 끝'과 진행 막대가 보인다.
  • 실패한 공문에 이유와 '다시 시도'가 나온다. 인터넷·API 키·사용 한도 문제를 구분해 안내한다.

8. 비기능 요구사항

  • 성능: 공문 1건 정리는 클로드 응답 시간에 좌우된다(측정 전). 여러 건을 정리할 때는 진행 상황을 보여 주어 기다림을 줄인다.
  • 보안 / 개인정보:
    • 로컬 서버는 이 PC 안의 접속(127.0.0.1)만 받는다.
    • 화면에는 PC 안의 파일 경로를 내보내지 않고, 공문에 기록된 파일만 열 수 있다(../../비밀.txt 같은 요청 차단을 시험으로 확인).
    • 클로드로 보내기 전 개인정보 알림, 기본값 '보내지 않기'.
    • Anthropic API로 보낸 내용은 기본적으로 모델 학습에 쓰이지 않고 30일 안에 삭제된다(정책 위반 의심 등 예외 있음, Anthropic 개인정보 안내 2026년 7~8월 기준).
    • API 키는 화면에 가려서 보이고, 공문함·기록·화면 응답에 그대로 남기지 않는다(티켓 02에서 구현).
  • 접근성: 버튼과 날짜 칸에 읽기 쉬운 이름(aria-label), 키보드 포커스 표시, 움직임 줄이기 설정 존중, 모든 안내 문구는 쉬운 우리말.
  • 호환성: 윈도우 학교 PC + 브라우저(크롬·엣지). 파이썬 3.10 이상. 기본 기능은 추가 설치가 없고, PDF 검사는 pypdf, 한글 서식 초안은 lxml과 hwpx 스킬이 필요하다. 휴대폰 크기 화면에서도 달력과 목록이 위아래로 보인다.
  • 확장성: 클로드 연결을 바꿔 끼울 수 있는 부품으로 두어, 시험(가짜 클로드)·미리 받은 답·실제 API를 같은 화면에서 쓴다. 공유 기능·구글 캘린더 연동은 이후 단계에서 붙일 수 있게 범위 밖으로 두었다.

    5. 보고 공문이면 '텍스트 초안' 또는 '한글 서식 초안'을 만든다 → 직접 채울 칸을 확인해 마무리한다
    6. 제출하면 '제출 완료'를 누른다 → 목록·달력에 빨간 줄

11. 기술 고려사항

  • 영향받는 모듈 / 시스템:
    • 공문함 읽기(gongmunham), 정리 기록(records), 화면 뒤 창구(server), 달력(calendar), 개인정보 알림(privacy), 초안 저장(drafts), 한글 서식(hwpx_forms), 학교 정보(school), 오류 종류(errors), 정리·초안 지시문(prompt), 클로드 연결 부품(가짜·미리 받은 답·실제 API)
  • 데이터 모델 변경: 공문함 안 파일 두 개에만 저장한다.
    • 똑공다_기록.json: 공문마다 id, 날짜 폴더, 문서번호, 파일, 종류·제목·보낸 기관·요약, 날짜 목록(종류·짧은 이름·시작·끝·근거), 날짜 확인 필요, 우리 학교, 제출 완료, 직접 고침, 두 값, 보내지 않은 파일, 실패 이유, 초안 목록
    • 똑공다_학교정보.json: 학교명, 주소, 전화번호, 학교장명, 교감명, 학급·학생 수, 교원 현황
  • API / 인터페이스(화면 뒤 창구): /api/organize/check, /api/organize, /api/organize/status, /api/documents, /api/document, /api/calendar, /api/day, /api/submitted, /api/edit, /api/reorganize, /api/resolve, /api/draft(text/hwpx), /api/open, /api/school
  • 클로드 요청: 정리 지시문 v2(종류 규칙, 날짜 추측 금지, 날짜별 짧은 이름, 실제 참석일만, 우리 학교 찾기, 공문 속 지시 무시)와 결과 모양(JSON 스키마), 텍스트 초안 지시문 v1. 기본 모델 Claude Opus 5.5, 설정에서 바꿀 수 있음.
  • 테스트 방침:
    • 시험 지점은 '화면 뒤 창구' 하나(통합 수준). 가짜 공문함 + 가짜 클로드로 요금 없이 반복 시험한다.
    • 기능마다 시험을 먼저 쓰고 실패를 확인한 뒤 구현했다(TDD). 바로 통과한 시험은 기능을 일부러 망가뜨려 실패하는지 확인했다. 기록: app의 TDD_LOG_*.md
    • 화면(HTML)은 자동 시험 없이 실제 공문 파일로 사람이 확인하고 화면 그림으로 남겼다.
    • 현재 자동 시험 55개 모두 통과.

13. 가정, 제약, 의존성

  • 가정:
    • 선생님이 업무관리시스템에서 내려받은 공문을 날짜 폴더에 직접 넣는다.
    • 공문 파일 이름에 '기관명-번호 (본문/첨부)' 모양의 접수번호가 붙는다(두 가지 모양 확인).
    • 보고 서식이 hwpx이거나, 선생님이 hwp를 hwpx로 다시 저장할 수 있다.
  • 제약:
    • 클로드 사용에 API 키와 사용료가 필요하다(시제품은 아티 선생님 키 하나로 시험).
    • hwpx 스킬은 .hwpx만 만들 수 있고, 칸마다 글자 수 예산이 엄격하다.
    • 이 개발 환경에는 한글 프로그램이 없어 실제 쪽수·줄바꿈은 사람이 확인해야 한다.
    • hwpx 스킬은 사용 조건(라이선스) 표시가 없어 앱에 복사하지 않고 설치 위치를 지정해 쓴다.
  • 의존성:
    • Anthropic Claude API(정리·초안)
    • hwpx 스킬(선생님이 받은 스킬 파일)
    • 파이썬 3.10+, pypdf(PDF 검사), lxml(한글 서식)
    • 학교 PC의 기본 프로그램(한글·엑셀·PDF 뷰어)으로 원본·초안 열기

14. 리스크와 대응

리스크가능성영향대응 방안
클로드가 날짜·종류를 잘못 판단중상날짜마다 근거 문장 표시, 추측 금지·'날짜 확인 필요', 직접 고침과 두 값 고르기

공문함선생님이 PC에 만들어 두는 최상위 폴더. 모든 날짜 폴더가 이 안에 있다.
날짜 폴더공문함 안에 날짜별로 만드는 폴더(예: 1121). 그날 내려받은 공문을 넣는다.
공문본문 하나와 거기에 딸린 붙임을 합친 한 묶음
문서번호파일 이름에 (본문)·(첨부)와 함께 붙은 '기관명-번호'(학교의 접수번호). 같은 번호의 본문과 붙임이 한 공문이 된다.
본문 / 붙임공문의 본체 파일(보통 PDF) / 본문에 딸린 파일(한글·엑셀·PDF). hwp와 hwpx가 함께 있으면 하나의 붙임으로 본다.
보고 / 일정 / 안내 공문기한까지 제출·회신해야 하는 공문 / 연수·행사·출장 날짜를 챙길 공문 / 읽고 알아 두면 되는 공문
마감일 / 행사일 / 신청 기간제출·회신 기한 / 실제로 모이거나 참석하는 날 / 신청·접수를 받는 기간
