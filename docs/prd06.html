동글이 책방 PRD — 독서교육 웹앱 공유 홈페이지

Nov 24, 2026 · @주경

1. 개요

한 줄 정의: 선생님이 AI 바이브코딩으로 만든 독서교육 웹앱과 독서 프로그램 아이디어를 그림책·독서토론·독서행사·문학기행 4개 테마로 모아 보여 주고, 다른 학교 선생님이 3분 안에 찾아 수업에 바로 쓰는 공유 홈페이지. 사이트 이름은 「동글이 책방」입니다.

배경: 초등학교 사서교사가 클로드 코드로 독서퀴즈, 북큐레이션, 독서행사 운영 도구 같은 웹앱을 만들어 왔습니다. 지금은 앱마다 주소가 흩어져 있어 공유가 어렵고, 업데이트 소식도 전할 곳이 없습니다.

해결할 문제

  • 흩어진 웹앱 주소를 한곳에서 찾고 실행할 수 없다.
  • 다른 선생님은 어떤 학년·수업·행사에 쓰면 좋은지 알 수 없다.
  • 다른 교사가 만든 앱을 올리고 함께 쓰는 통로가 없다.
  • 앱이 고쳐지거나 새로 나와도 알릴 방법이 없다.

목표 (출시 후 1학기 기준)

  • 앱 20개 이상 등록, 제작 교사 10명 이상 참여
  • 처음 온 교사가 원하는 앱을 3분 안에 찾아 실행
  • 가입 없이 둘러보기·실행 가능, 등록만 로그인
  • 화면은 세련되게, 그러나 학교 PC와 오래된 태블릿에서도 빠르게

하지 않을 것 (MVP 범위 밖): 앱 자체를 사이트 안에서 코딩하는 기능, 유료 판매, 학생 개인정보를 모으는 기능.

2. 대상 사용자

핵심 사용자는 ‘앱을 쓰는 교사’이고, 그다음이 ‘앱을 올리는 교사’입니다. 학생은 교사가 준 링크로 앱만 실행합니다.

사용자상황필요한 것우선순위
쓰는 교사 (초·중·고 담임·국어·사서교사)다음 주 독서수업·도서관 행사 준비, 코딩 경험 없음학년·목적별 필터, 수업 활용 예시, 바로 실행 링크와 QR높음
올리는 교사 (바이브코딩 제작자)클로드 코드 등으로 앱을 만들어 배포 주소가 있음5분 안에 끝나는 등록 양식, 업데이트 기록, 반응 확인높음
운영자 (사서교사 본인)사이트 관리, 추천 선정등록 검수, 추천 고정, 공지·업데이트 소식 작성중간
학생수업 중 태블릿·크롬북으로 접속QR·짧은 링크로 앱 화면만 바로, 로그인 없음낮음

대표 페르소나

  • 김선생님 (중학교 국어, 12년차): ‘한 학기 한 권 읽기’ 수업에서 토론 도구를 찾는다. 코딩은 모르고, 수업 예시가 있어야 믿고 쓴다.
  • 박사서교사 (초등, 5년차): 바이브코딩으로 독서빙고 앱을 만들었다. 연수·모임에서 공유할 한 주소가 필요하다.

3. 핵심 사용 시나리오

  1. 찾아서 바로 쓰기: 교사는 홈에서 ‘중학교 · 토론’ 필터를 누르고, 카드의 미리보기를 본 뒤 ‘수업에서 열기’로 전체화면 실행한다.
  2. 학생에게 나눠주기: 상세 페이지의 QR과 짧은 링크를 칠판·TV에 띄운다. 학생은 로그인 없이 앱에 들어간다.
  3. 수업 준비: 상세 페이지에서 ‘수업 활용 예시’(차시 흐름, 소요시간, 추천 도서)와 활동지 PDF를 받는다.
  4. 내 앱 올리기: 제작 교사는 로그인 후 앱 주소, 제목, 대상 학교급, 활용 유형, 한 줄 소개, 스크린샷을 넣고 제출한다. 운영자 검수 후 공개된다.
  5. 업데이트 알리기: 제작 교사가 버전과 변경 내용을 적으면, 앱 카드에 ‘업데이트’ 배지가 붙고 사이트 ‘새 소식’에 쌓인다.
  6. 후기 남기기: 쓴 교사가 ‘수업에 썼어요’를 누르고 한 줄 후기를 남긴다. 제작 교사에게 다음 개선의 근거가 된다.

3-1. 4대 테마와 카테고리 구조

동글이 책방의 대분류는 그림책 · 독서토론 · 독서행사 · 문학기행 4개 테마입니다. 각 테마 안에서 ‘웹앱’과 ‘독서 프로그램 아이디어’ 두 종류의 자료를 봅니다. 테마는 코드에 고정하지 않고 관리자 화면에서 추가·변경합니다.

테마담는 것웹앱 예시프로그램 아이디어 예시
1. 그림책그림책 함께 읽기, 그림책 창작장면 순서 맞추기, 나만의 그림책 표지 만들기그림책 하브루타 수업, 학년별 그림책 큐레이션
2. 독서토론질문 만들기, 찬반·하브루타 토론토론 질문 생성기, 찬반 타이머·발언 기록판한 학기 한 권 읽기 토론 차시안, 독서토론 대회 운영안
3. 독서행사독서의 달, 도서관 주간, 작가와의 만남독서 빙고, 북 퀴즈 대회, 도서관 방탈출독서의 달 행사 키트, 작가 초청 준비 체크리스트
4. 문학기행작가·작품 배경지 탐방, 지역 문학관작품 배경지 문학 지도, 기행 미션 스탬프기행 사전·사후 활동지, 지역별 문학관 코스

자료는 두 종류

자료 유형필수 항목상세 화면
웹앱앱 주소, 스크린샷, 한 줄 소개‘수업에서 열기’, QR, 수업 활용 예시, 버전 기록
프로그램 아이디어개요, 대상 학교급, 차시 흐름차시별 흐름, 준비물, 첨부 활동지(hwp·pdf 등), 함께 쓰면 좋은 웹앱 연결
  • 자료마다 대표 테마 1개를 고르고, 필요하면 다른 테마 2개까지 함께 표시합니다 (예: ‘그림책 토론 질문 생성기’ → 그림책 + 독서토론).
  • 테마 페이지(/theme/picture-books 등)는 테마 소개 배너, ‘웹앱 / 프로그램 아이디어’ 탭, 학교급 필터, 최신·인기 정렬로 구성합니다.
  • 테마마다 아이콘과 테마 색을 두고, 카드·배지·테마 배너에 같은 색을 씁니다.

카테고리를 쉽게 늘리고 고치는 구조

핵심 원칙: 테마 목록은 코드가 아니라 DB의 categories 테이블에서 읽습니다. 그래서 관리자 화면에서 저장하면 메뉴·홈·필터·등록 양식에 바로 나타나고, 배포가 필요 없습니다.

  • 추가: 이름, 주소용 영문 이름(예: reading-club), 한 줄 소개, 아이콘, 테마 색을 넣고 저장합니다.
  • 이름 변경: 화면에 보이는 이름만 바뀌고 주소는 그대로라, 이미 공유한 링크가 깨지지 않습니다.
  • 순서: 끌어서 놓으면 메뉴와 홈 테마 카드 순서가 함께 바뀝니다.
  • 숨기기: 준비 중인 테마를 미리 만들어 자료를 채운 뒤, 공개 스위치를 켭니다.
  • 삭제: 자료가 남아 있는 테마는 바로 지울 수 없고, ‘다른 테마로 옮기기’를 거쳐야 삭제됩니다.
  • 세부 분류 (선택): 테마 아래 한 단계까지 둘 수 있습니다 (예: 독서행사 > 독서의 달 · 도서관 주간 · 작가와의 만남).
  • 새 테마가 늘어도 안 깨지는 화면: 홈 테마 카드는 개수에 맞춰 줄바꿈하고, 상단 메뉴는 테마가 5개를 넘으면 ‘테마 전체’ 펼침 메뉴로 바뀝니다.
  • 학교급·활동 태그도 같은 화면에서 같은 방식으로 관리합니다.

나중에 테마를 늘릴 후보: 도서관 이용교육, 독서동아리, 인문학 독서, 디지털 리터러시.

4-1. 관리자 모드

관리자는 /admin 별도 화면에 비밀번호로 들어가, 코딩 없이 앱·파일·공지·사이트 설정을 고칩니다. 교사의 앱 올리기는 구글 로그인, 관리자는 이와 분리된 비밀번호로 들어갑니다.

메뉴할 수 있는 일
대시보드검수 대기 수, 테마별 자료 수, 이번 주 새 자료, 최근 올라온 파일, 링크 점검 실패 목록, 인기 검색어·결과 없는 검색어, 태그 없는 자료 수
자료 관리웹앱·아이디어를 표에서 바로 수정·숨김·삭제, 여러 개 골라 테마 옮기기·일괄 처리, 추천 고정, 끌어서 순서 변경
카테고리 관리테마·세부 분류·학교급·활동 태그 추가, 이름·아이콘·색 변경, 순서 끌기, 숨김·삭제 (3-1 참고). 태그 이름 변경·합치기·동의어·일괄 태그 (4-3 참고)
검수함승인·반려, 반려 사유는 자주 쓰는 문구 중 고르기
파일함사이트 전체 첨부 파일 검색, 교체, 삭제, 휴지통에서 복원
새 소식·공지글 작성, 예약 게시, 홈 상단 공지 배너 켜기·끄기
사이트 설정사이트 이름, 로고, 히어로 문구, 푸터 연락처, 점검 중 배너
비밀번호·보안비밀번호 변경, 최근 로그인 기록

관리자 비밀번호 규칙

  • 초기 비밀번호는 0000입니다. 첫 로그인 직후 ‘새 비밀번호 설정’ 화면이 뜨고, 바꾸기 전에는 다른 메뉴가 열리지 않습니다. 0000은 누구나 짐작할 수 있어 공개 사이트에 그대로 두면 위험하기 때문입니다.
  • 홈페이지 안에서 변경: 관리자 > 비밀번호·보안에서 현재 비밀번호 확인 후 새 비밀번호를 두 번 입력합니다. 8자 이상, 숫자만으로는 불가.
  • 저장 방식: 비밀번호는 원문이 아니라 해시(bcrypt)로만 DB에 저장합니다. 초기값 0000도 코드에 적지 않고 Vercel 환경변수 ADMIN_INITIAL_PASSWORD로 넣습니다.
  • 잠금: 5회 틀리면 10분 잠금, 로그인 후 2시간이 지나면 자동 로그아웃.
  • 분실 시: 저장소의 scripts/reset-admin.ts를 실행해 0000으로 되돌리고, 다시 첫 로그인 변경 절차를 밟습니다.

4-2. 파일 업로드와 수정·삭제

끌어다 놓기 한 번으로 여러 파일을 올리고, 올린 뒤에도 그 자리에서 이름 바꾸기·교체·순서 변경·삭제를 합니다. 앱마다 활동지, 수업 PPT, 평가표 같은 자료를 함께 붙일 수 있습니다.

올리기

  • 끌어다 놓기, ‘파일 선택’, 휴대폰에서는 사진 바로 촬영. 여러 개 동시에, 파일마다 진행률 표시.
  • 용량은 파일당 20MB, 앱당 합계 100MB. 무료 저장공간(1GB)을 오래 쓰기 위한 기준입니다.
  • 앱 등록 양식 안에서 바로 첨부하므로, 앱 정보와 자료를 한 번에 제출합니다.

수정·삭제

  • 파일 이름과 한 줄 설명은 클릭해서 바로 고칩니다.
  • ‘파일 교체’를 누르면 같은 자리에 새 버전이 들어가고, 이전 파일은 버전 기록에 남습니다.
  • 삭제하면 휴지통으로 가고 30일 안에 복원할 수 있습니다. 30일 뒤 자동으로 지워집니다.
  • 여러 파일을 골라 한 번에 삭제·다운로드(zip)할 수 있습니다.
  • 교사는 ‘내 앱’에서 자기 앱 정보와 파일만, 관리자는 전체를 수정·삭제합니다. 앱 주소(URL)를 바꿀 때만 다시 검수합니다.

안전장치

  • 확장자와 실제 파일 형식(MIME)을 둘 다 확인하고, 실행 파일(exe, js, html, bat 등)은 막습니다.
  • 저장할 때 파일명은 무작위로 바꾸고, 원래 이름은 화면에만 보여 줍니다.
  • 학생 이름·사진이 담긴 파일은 올리지 않도록 업로드 창에 안내 문구와 확인 체크를 둡니다.

4-3. 검색·색인·태그

자료가 수백 개로 늘어도 처음 온 교사와 관리자가 원하는 자료를 30초 안에 찾도록, 통합 검색·가나다 색인·태그 세 가지 길을 둡니다. 세 기능 모두 P0입니다.

찾는 길이럴 때예
통합 검색떠오르는 단어가 있을 때“빙고”, “강아지똥”, “ㄷㅅㅌㄹ”
색인무엇이 있는지 한눈에 훑어보고 싶을 때가나다순 전체 목록, 도서명별 목록
태그비슷한 자료를 이어서 보고 싶을 때#모둠활동 #9월독서의달 누르기

통합 검색

  • 위치: 모든 화면 상단의 검색창과 홈 히어로의 큰 검색창. 키보드 /를 누르면 바로 열립니다.
  • 찾는 범위: 제목, 한 줄 소개, 태그, 테마, 제작자, 차시 흐름 본문, 관련 도서명·작가, 첨부 파일 이름.
  • 한글에 맞춘 검색: 초성 검색(ㄱㄹㅊ → 그림책), 띄어쓰기 무시(독서 토론 = 독서토론), 비슷한 철자 허용, 동의어(토의 = 토론, 북퀴즈 = 독서퀴즈).
  • 자동완성: 글자를 치는 동안 자료 5개, 태그 3개, 테마를 미리 보여 줍니다.
  • 결과 화면: 테마·자료 유형·학교급·태그 필터 칩, 정렬(관련도·최신·인기), 검색어 강조 표시. 필터 상태는 주소에 남아 그대로 공유할 수 있습니다.
  • 결과가 없을 때: 비슷한 태그와 인기 자료를 보여 주고, ‘이런 자료가 있으면 좋겠어요’ 요청을 남기게 합니다.
  • 최근·인기 검색어: 검색창을 누르면 내 최근 검색어(이 기기에만 저장)와 이번 주 인기 검색어가 뜨엉니다.
  • 관리자 검색: 관리자 화면에서도 같은 검색에 상태(검수 중·숨김·휴지통)·제작자·등록일 필터를 더하고, 결과를 골라 일괄 수정합니다. 대시보드에는 ‘결과 없는 검색어’ 목록이 뜨서 다음에 만들 자료의 단서가 됩니다.

색인 (전체 목록 페이지)

  • /index 페이지를 두고 상단 메뉴와 푸터에 ‘색인’ 링크를 둡니다.
  • 보기 전환 5가지: 가나다순 / 테마별 / 태그별 / 도서명별(그 책으로 쓸 수 있는 자료) / 학교급별.
  • 가나다순 보기에는 ㄱ–ㅎ, A–Z 머리글자 바를 두어 누르면 그 자리로 건너뜁니다.
  • 한 줄에 자료 하나(제목 · 테마 · 자료 유형 · 학교급)를 보여 주는 촘촘한 목록이며, 인쇄하면 연수·안내 자료로 쓸 수 있게 인쇄용 화면을 따로 둡니다.

태그

태그는 두 층입니다. 관리자가 정해 둔 ‘고정 태그 그룹’에서 고르고, 그 밖의 키워드는 ‘자유 태그’로 더합니다.

태그 그룹예등록 때
학교급초1–2, 초3–4, 초5–6, 중, 고필수, 여러 개 선택
활동퀴즈, 토론, 글쓰기, 게임, 만들기, 탐방선택
수업 형태개인, 모둠, 전체, 원격선택
시기·행사3월 신학기, 4월 도서관 주간, 세계 책의 날, 9월 독서의 달선택
도서책 제목·작가입력하면 기존 도서 자동완성
자유 태그아무 키워드입력하면 기존 태그 자동완성
  • 붙이기: 등록 양식에서 그룹별 칩을 누르고, 자유 태그는 입력 중 기존 태그가 먼저 뜨서 ‘토론’·‘토론활동’ 같은 중복을 막습니다. 자료당 최대 10개.
  • 따라가기: 카드와 상세 화면의 태그를 누르면 그 태그의 자료 목록(/tag/모둠활동)으로 갑니다. 상세 화면 아래에는 태그가 많이 겹치는 ‘비슷한 자료’ 4개를 보여 줍니다.
  • 관리자 태그 관리: 이름 변경, 합치기(‘토의’를 ‘토론’으로 합치면 붙어 있던 자료도 자동 이동), 동의어 등록, 숨김·삭제, 태그별 사용 횟수 확인.
  • 일괄 태그: 관리자가 검색 결과에서 여러 자료를 골라 태그를 한꺼번에 붙이거나 떼며, ‘태그가 비어 있는 자료’ 목록으로 정리할 것을 찾습니다.
  • 태그 추천 (P1): 제목과 소개에 나오는 단어를 보고 알맞은 태그를 미리 골라 줍니다. 등록자는 확인만 합니다.

구현과 기준

  • Supabase Postgres의 전문 검색과 pg_trgm(비슷한 철자)으로 시작하고, 초성은 저장할 때 따로 뽑아 두어 빠르게 찾습니다. 자료가 2,000개를 넘어 느려지면 전용 검색 서비스(Meilisearch 등)로 옮깁니다.
  • 검색 결과는 0.5초 안에, 자동완성은 글자 입력 후 0.2초 안에 뜬니다.
  • 검색어 기록은 검색어와 결과 수만 남기고, 누가 검색했는지는 저장하지 않습니다.
  • 성공 기준: ‘결과 없음’ 검색 비율 10% 이하, 처음 온 교사 5명 테스트에서 검색·색인으로 원하는 자료를 30초 안에 찾기.

클로드 코드에 맡길 때의 요청:

동글이 책방에 통합 검색을 넣어 줘. Supabase 전문 검색 + pg_trgm을 쓰고,
제목·소개·태그·도서명·차시 본문을 찾게 해 줘.
초성 검색과 띄어쓰기 무시를 지원하고, 입력 중 자동완성(자료 5·태그 3)을 보여 줘.
결과 화면에는 테마·자료 유형·학교급·태그 필터를 두고, 필터 상태를 주소에 남겨 줘.
먼저 샘플 자료 30개로 테스트하고, “ㄱㄹㅊ”과 “독서 토론”이 찾아지는지 보여 줘.

6. 디자인 방향

콘셉트는 **‘빛이 드는 조용한 도서관’**입니다. 비싼 스타트업 사이트의 화면 효과를 쓰되, ‘어디에 하나만 둘지’를 원칙으로 합니다. 효과는 방문자 기기에서 그래픽을 돌리므로, 학교의 오래된 PC와 태블릿을 기준으로 절제합니다.

검색어 기록은 search_logs(query, result_count, searched_at)에 두며 검색한 사람은 저장하지 않습니다. 처음 배포할 때 categories에 4개 테마(picture-books, book-talk, reading-events, literary-trips)를 기본값으로 넣습니다. 이후 추가·변경은 관리자 화면에서만 합니다. 파일 본체는 Supabase Storage에 두고, 삭제는 deleted_at만 채워 30일 안에 복원할 수 있습니다.

파일 본체는 Supabase Storage에, 목록·설명은 files 테이블에 둡니다. 삭제는 deleted_at만 채우는 방식이라 30일 안에 복원할 수 있습니다.

9-1. 업데이트와 배포 운영

내용 변경은 관리자 화면에서 바로 반영하고, 기능·디자인 변경은 GitHub에 올리면 Vercel이 자동 배포합니다. 문제가 생기면 이전 배포로 1분 안에 되돌립니다.

바꾸는 것방법배포
앱·파일·공지·문구·분류관리자 화면필요 없음 (저장 즉시 반영)
화면 디자인·새 기능클로드 코드 → GitHub → Vercel자동
DB 구조(테이블·칸 추가)supabase/migrations 파일로 기록자동, 미리보기에서 먼저 확인

기능을 바꿀 때의 순서

  1. 클로드 코드에서 새 브랜치를 만들고 수정합니다 (예: feature/file-upload).
  2. GitHub에 올리면 자동 검사(빌드·린트·타입 검사)가 돌고, 실패하면 배포되지 않습니다.
  3. Vercel이 브랜치마다 미리보기 주소를 줍니다. 휴대폰·크롬북으로 열어 보고, 필요하면 동료에게 먼저 보여 줍니다.
  4. 괜찮으면 main에 합치고, 실제 사이트에 자동 배포됩니다.
  5. 문제가 보이면 Vercel의 Instant Rollback으로 직전 배포를 골라 되돌립니다.

운영 규칙

  • 버전 번호: v1.0.0에서 시작하고, 배포할 때마다 CHANGELOG.md와 ‘새 소식’에 기록합니다. 새 소식은 ‘사이트 업데이트’와 ‘앱 업데이트’ 태그로 나눕니다.
  • 배포 시간: 수업 중 화면이 바뀌지 않도록 방과 후나 주말에 합니다.
  • 점검 배너: 큰 변경 전에는 관리자 설정에서 ‘점검 중’ 배너를 켭니다.
  • 백업: 주 1회 DB를 백업하고, 파일함은 관리자 화면에서 zip으로 내보낼 수 있게 합니다.
  • 비밀 값: Supabase 키, 초기 관리자 비밀번호는 Vercel 환경변수에만 두고 GitHub에 올리지 않습니다.

클로드 코드가 매번 같은 규칙을 따르게 하는 요청

프로젝트 루트에 CLAUDE.md를 만들어 줄래? 내용:
- 모든 수정은 새 브랜치에서 하고, main에 직접 올리지 마.
- 올리기 전에 npm run build와 npm run lint가 통과하는지 확인해.
- DB를 바꾸면 supabase/migrations에 파일로 남겨.
- 바꾼 내용은 CHANGELOG.md에 버전과 함께 한 줄로 적어.
- 비밀번호·키는 코드에 쓰지 말고 환경변수로만 써.
