0. 한눈에 보는 제품

글눈 150은 초성·중성의 음운 조합 원리를 이해하거나 적용하는 데 어려움이 있지만 발화가 가능한 특수교육대상학생을 위한 한글 읽기 학습 프로그램이다. 받침 없는 개음절 150개를 통문자처럼 형태와 소리를 직접 연결하여 학습하도록 한다.

핵심은 화려한 게임이 아니라 정확한 반복학습과 학습 효율이다. 학습자가 읽을 수 있게 된 음절은 기본 반복 목록에서 제외하고, 아직 읽지 못하는 음절만 집중적으로 연습한다. 개별 음절의 평가와 숙달 상태를 온라인에 기록해 기기가 바뀌어도 이어서 학습한다.

제품의 최종 학습 성취 기준은 글자를 따라 쓸 수 있는가가 아니라 화면에 제시된 음절을 보고 스스로 읽을 수 있는가이다. 따라 쓰기는 보조 학습 활동이며, 발화 평가는 핵심 읽기 평가 활동이다.

0.1 브랜드 및 화면 문구 지침

  • 공식명: 글눈 150 (띄어쓰기 포함, 전체 UI·관리자 화면·메타데이터·문서에서 동일하게 사용).
  • 이름의 의미: 한글을 보고 소리 내어 읽는 능력, 즉 ‘글눈이 트이는’ 경험을 학생별 150개 음절 숙달 과정으로 표현한다.
  • 학습자에게 보이는 서비스 소개: 글자를 보고, 듣고, 써 보고, 읽어요.
  • 교육자에게 보이는 설명: 음운 조합 원리 이해가 어려운 발화 가능 학생을 위한 150개 개음절 통문자식 읽기 학습.
  • 임시 홍보 문구(선택 사항, 미확정): 한 글자씩, 읽는 눈이 트이다.
  • 텍스트 사용 기준: 학생 화면에서는 개음절, 종성, 숙달 같은 전문용어보다 글자, 읽기, 다시 배우기, 읽을 수 있어요 등 쉬운 표현을 사용한다.

1. 문제 정의와 교육적 근거

1.1 해결하려는 문제

  • 일반적인 한글 입문 교육은 자음·모음의 소리를 인식하고 결합하여 음절을 읽는 방법을 중심으로 한다.
  • 일부 특수교육대상학생은 이러한 추상적 음운 조합 원리를 이해하고 적용하는 과정에서 지속적인 어려움을 겪는다.
  • 이미 읽을 수 있는 음절을 계속 반복하면 시간이 낭비될 수 있고, 학생별 미습득 음절을 교사가 일일이 분류·기록하기 어렵다.
  • 기존의 게임 중심 설계만으로는 반복 횟수, 음절별 읽기 확인, 개인화된 재학습이 충분히 관리되지 않을 수 있다.

1.2 교수·학습 가설

  • 초성·중성의 조합 원리 학습을 초기 필수 단계로 요구하지 않고, 개음절 하나를 완성된 시각·청각 단위로 학습하는 경로를 제공한다.
  • 받침 없는 음절을 충분히 읽게 된 이후, 필요에 따라 종성받침을 덧붙이는 단계로 확장할 수 있다.
  • 개음절 학습이 종성 학습을 반드시 쉽게 만든다는 점은 모든 학생에 대한 확정적 사실이 아니라 검증할 교육적 가설로 취급한다.
  • 글눈 150은 음운 조합 교수법 전체를 부정하거나 대체하기 위한 도구가 아니라, 특정 학습자 집단에 제공할 수 있는 대안적 학습 경로이다.

1.3 제품 원칙(우선순위 순)

  1. 읽기 습득: 화면의 문자만 보고 해당 음절을 소리 내어 읽을 수 있도록 한다.
  2. 미습득 집중: 정답 음절은 반복·평가의 기본 대상에서 자동 제외한다.
  3. 개별화: 학생마다 학습 목록·평가 결과·자음별 완료 여부가 다르다.
  4. 인지 부담 최소화: 한 번에 한 음절, 큰 글자, 적은 버튼, 일관된 화면.
  5. 안전한 실패 처리: 음성 인식 실패를 읽기 실패로 단정하지 않는다.
  6. 디자인은 보조 수단: 칭찬과 가벼운 시각적 보상은 제공하되 경쟁·과도한 애니메이션·복잡한 게임은 지양한다.

2. 학습 대상과 사용자 역할

2.1 1차 학습 대상

  • 인지·학습 특성상 한글 음운 조합 원리를 이해·적용하기 어려운 특수교육대상학생.
  • 발화가 가능하며, 화면에 나타난 음절을 소리 내어 읽는 활동에 참여할 수 있는 학생.
  • 문해력 및 조음 능력에는 큰 개인차가 있으므로 발화 가능 여부만으로 자동 판정 적합성을 보장하지 않는다.
  • 장애명·장애 정도를 앱의 필수 입력 항목으로 요구하지 않는다.

3. 성공 지표와 비목표

3.1 성공 지표

  • 학생별 150개 목표 음절 중 읽기 평가를 통과한 음절 수/비율.
  • 음절별 평균 평가 시도 횟수, 오답 후 정답 전환율.
  • 재방문 후 이전 학습 진도 복원 성공률.
  • 음성 인식의 유효 판정 비율과 교사 확인 결과 대비 일치율.
  • 학습 완료 음절이 기본 반복 목록에서 중복 출제되지 않는 비율(목표 100%).

3.2 이번 범위에서 제외

  • 종성(받침) 교육, 단어·문장 읽기, 음운 조합 원리의 체계적 교수.
  • 장애 진단·평가, 자동 학습능력 진단, 개인별 처방을 AI가 단독 결정하는 기능.
  • 경쟁 순위표, 결제·광고, 학생 간 소셜 기능.
  • 오프라인 전체 학습 보장, 네이티브 앱 배포.

4. 음절 콘텐츠 구성

4.1 목표 범위

  • 음절 수: 정확히 150개(콘텐츠 확정 시 중복 없는 목록).
  • 자음 선택 UI: 기본 자음 ㄱ ㄴ ㄷ ㄹ ㅁ ㅂ ㅅ ㅇ ㅈ ㅊ ㅋ ㅌ ㅍ ㅎ의 14개 메뉴를 1차 범위로 제안한다.
  • 쌍자음(ㄲ ㄸ ㅃ ㅆ ㅉ) 포함 여부는 별도 결정 항목이다. 150개를 반드시 자음별 동일 개수로 배분하지 않는다.
  • ㅇ은 초성 위치에서 별도 자음 소리가 없으므로 관련 음절의 실제 발음 음성만 제시한다.
  • 음절 선정 시 일상적 사용 빈도, 학생의 생활 어휘와의 관련성, 발음의 명확성, 교육적 유용성, 자음군 균형을 검토한다.
  • 됴와 같은 드문 음절은 원칙적으로 제외한다. 다만 흔한 음절이라고 판정하려면 실제 빈도 자료와 교사 검토가 필요하다.
  • 글눈 150 PRD는 150개의 확정 목록을 임의로 만들어 넣지 않는다. 콘텐츠 선정은 개발 착수 전 별도 syllables.v1.json으로 확정·검증한다.

4.2 음절당 데이터

  • 고유 ID, 음절(예: 가), 초성 분류, 중성, 표시 순서, 활성화 여부.
  • 표준 발음 음성 파일 경로(mp3 또는 ogg), 재생 길이 및 저작권/제작 정보.
  • 따라 쓰기 가이드(필요시 좌표/획 템플릿); 단순 표준 글꼴 윤곽선만으로 정확한 획순 판정은 하지 않는다.
  • 콘텐츠 버전 및 선택 근거(빈도 등급·생활 관련성·교사 검토 여부).

4.3 콘텐츠 검증 기준

  • 150개 모두 Unicode 한글 완성형 음절이고 종성 받침이 없는지 자동 검증한다.
  • 정확히 150개이며 중복이 없어야 한다.
  • 각 음절이 초성 메뉴 하나에 정확히 연결된다.
  • 모든 음절의 음성 파일이 존재하고 오디오 내용이 해당 음절과 일치하는지 사람의 검수를 거친다.
  • 목록 버전 변경 시 기존 학습 기록을 임의로 삭제하거나 다른 음절에 연결하지 않는다.

5.4 UI·접근성 원칙

  • 안드로이드 태블릿 가로 모드 우선, 세로 모드에서도 사용 가능하도록 반응형 구성.
  • 한 화면에 가급적 핵심 작업 하나, 버튼 크기 충분히 확보(터치 영역 권장 48px 이상), 아이콘에 텍스트 병기.
  • 색상만으로 상태를 전달하지 않고 완료 ✓, 학습 중, 미학습 텍스트·아이콘을 함께 사용.
  • 학생 닉네임은 로그인 이후 학생 화면 공통 헤더에 계속 표시.
  • 실수로 화면을 벗어나지 않도록 명확한 이전/홈 동작, 저장 상태를 알기 쉽게 표현.
  • 음향·시각 자극은 제한하고, 오류에 대해 부정적 평가 문구 대신 재시도와 정답 소리를 제공.

6. 기능 요구사항 (Functional Requirements)

FR-01. 글눈 150 계정·인증·승인 [P0]

  1. 글눈 150 회원가입, 로그인, 로그아웃을 제공한다.
  2. 학생 가입은 보호자·교사의 도움을 전제로 설계할 수 있다. 초기 인증 구현은 Firebase Authentication의 이메일/비밀번호 방식을 기본으로 하며, 별도의 숫자 ID/PIN 로그인은 별도 인증 설계가 필요하다.
  3. 가입 후 상태는 pending이며 관리자가 승인하기 전에는 학습을 시작할 수 없다.
  4. 계정 상태는 pending / active / suspended로 관리한다.
  5. 관리자는 회원 목록을 조회하고 승인/정지/닉네임 변경/학습기록 초기화를 수행한다(초기화는 재확인 절차와 기록 필요).
  6. 학생이 관리자 권한을 직접 부여할 수 없어야 한다.
  7. 비밀번호 재설정은 인증 서비스가 지원하는 안전한 방식으로 구현하고, 관리자에 의한 타 사용자 비밀번호 직접 변경은 기본 웹 클라이언트 기능으로 가정하지 않는다.

FR-02. 닉네임 고정 표시 [P0]

  • 승인된 사용자가 로그인하면 학생 화면의 공통 상단 헤더에 닉네임을 계속 표시한다.
  • 새로고침하거나 다른 기기로 로그인해도 같은 닉네임을 표시한다.

FR-03. 자음 학습 메뉴 및 상태 [P0]

  • 상단에는 글눈 150 제품명, 닉네임, 자음 학습 메뉴를 지속적으로 표시한다.
  • 1차 범위에서 14개 기본 자음 메뉴를 제시한다(쌍자음 5개 포함 여부는 결정 대기).
  • 미학습/학습 중/완료를 구분한다.
  • completed인 자음에는 ✓(V) 표시를 붙인다.
  • 완료 자음도 사용자가 복습 모드로 다시 들어갈 수 있다. 복습한 사실이 완료 상태를 자동으로 해제하지는 않는다.
  • 전체와 자음별 숙달 현황을 개인별로 표시한다.

FR-04. 음절 학습 [P0]

  • 선택 자음의 학습 대상 음절 중 미습득 음절을 우선 제시한다.
  • 한 화면에 큰 음절 한 개를 중심으로 제시한다.
  • 듣기 버튼을 누르면 해당 음절 소리를 정확히 1회 재생한다.
  • 학습 화면에 진입하는 즉시 자동 재생하지 않는다.
  • 학생은 따라 쓰기를 하거나 복습할 수 있다.
  • 쓰기 검증을 통과하면 다음 음절 버튼을 사용할 수 있다. 운동·필기 어려움이 있는 학생을 위해 교사의 수동 통과/쓰기 생략 옵션도 지원한다.
  • 쓰기 성공은 읽기 숙달 판정과 구별한다.

FR-05. 따라 쓰기 [P0]

  • HTML Canvas와 Pointer Events를 활용하여 손가락·정전식 펜·S펜 입력을 받는다.
  • 화면에 음절 가이드(윤곽선 또는 경로)를 표시하고 그 위를 따라 쓰게 한다.
  • 초기 버전의 자동 검증은 지정된 경로/영역 통과율과 획 완성 여부에 대한 근사적 보조 판정이다.
  • 단순히 그림이 비슷하다는 이유로 정확한 획순이나 한글 쓰기 능력을 완벽히 검증했다고 주장하지 않는다.
  • 다시 쓰기/모두 지우기/쓰기 성공 여부 표시 기능을 제공한다.
  • 조작 어려움 및 기술적 오판을 위해 교사 보정·엄격도 조절 옵션을 둔다.

FR-06. 소리 재생 설정 [P0]

  • 1회 듣기: 스피커 버튼 터치마다 1회 재생.
  • 필기 중 반복 듣기: 학생이 필기를 시작할 때 일정 간격으로 동일 음절을 반복 재생하며 필기를 중단/종료하면 멈춤.
  • 둘 다 사용: 위 두 방식 동시 제공(기본 추천).
  • 반복 주기 초기값은 약 3초로 제안하며 사용자별 설정 가능. 재생 중 음성이 겹치지 않도록 한다.
  • 마이크 녹음이 시작되면 음절 음성 재생을 중지하여 정답 음성이 평가에 유입되지 않도록 한다.
  • 사용자 제스처 후 음성 재생을 시작하도록 하여 브라우저 자동재생 제한에 대응한다.
  • 실사용 서비스는 사람이 녹음한 150개 표준 음절 소리 파일을 우선 추천하며, TTS는 임시 개발 대체재로 사용한다.

FR-07. 5문항 읽기 평가 [P0: 기능 / P1: 자동 음성 인식]

  • 자음의 음절 학습을 마치면 평가에 진입할 수 있다.
  • 평가 단위는 최대 5문항이다. 아직 숙달되지 않은 해당 자음 음절 중 중복 없이 무작위 출제한다.
  • 기본 평가 화면에서는 글자를 크게 제시하고, 정답 소리를 먼저 재생하지 않는다.
  • 학생이 마이크 버튼을 눌러 해당 음절을 발음한다.
  • 음성 인식 결과가 목표 음절과 정확히 일치하는 경우 정답 후보로 처리한다. 최종 자동 판정 허용 여부는 현장 검증 후 결정한다.
  • 정답 판정 시 해당 음절을 mastered 처리하여 이후의 기본 학습 및 평가에서 제외한다.
  • 오답 판정 시 정답 소리를 1회 들려주고 미습득/재학습 상태로 유지한다.
  • 음성 미인식, 마이크 권한 거부, 네트워크 오류는 오답으로 기록하지 않는다. 다시 시도 또는 교사 확인 기능을 안내한다.
  • 음성 인식과 조음 정확도 판정은 다르다. 브라우저 인식기는 특히 단일 한글 음절 판정에 부적합할 수 있으므로 교사 확인/보정 수단이 필수다.

FR-08. 틀린 음절의 재학습·재평가 [P0]

  • 이전 평가에서 정답 처리된 음절은 후속 기본 평가 출제 목록에 포함하지 않는다.
  • 오답 음절은 재학습 목록에 남는다. 한편 한 번도 평가하지 않은 음절도 별도 관리하여 계속 평가 대상에 포함한다.
  • 다음 평가의 출제 우선순위는 오답 이력 있는 미습득 → 아직 미평가를 기본으로 하되, 편향 방지를 위해 설정으로 조절 가능하게 한다.
  • 남은 미습득 음절이 5개 미만이면 그 개수만 출제한다. 이미 맞힌 음절을 단순히 5개를 채우기 위해 재출제하지 않는다.
  • 평가 중 종료되어도 이미 저장된 정답은 유지되고 미완료 세션은 복원/재시작할 수 있다.

FR-09. 자음별 완료 판정 [P0]

  • 핵심 설계 해석: 5문항 미니 평가를 모두 맞힘과 해당 자음의 모든 목표 음절을 읽을 수 있음은 별도 개념이다.
  • 추천 기본 규칙: 해당 자음에 속한 모든 학습 대상 음절이 mastered 상태일 때 자음 메뉴에 ✓를 표시한다. 미니 평가 5문항 통과는 중간 성취로 기록한다.
  • 이 규칙이 원래 구상하신 최종 5문항 정답 시 해당 자음 완료와 다른 점은 승인 필요 설계 결정으로 남긴다. 단순 5개 샘플 통과만으로 전체 읽기 숙달을 보장하지 않기 때문이다.
  • 관리자가 숙달 상태를 수동 해제하면 해당 자음의 완료 상태도 자동 재계산한다.

FR-10. 학생별 온라인 저장 [P0]

  • 학생 계정마다 개별 음절 학습·평가·숙달 상태를 온라인 DB에 저장한다.
  • 주요 학습 이벤트 후 저장하고, 재접속/다른 기기 로그인 시 서버 데이터를 다시 불러온다.
  • 학습 진도는 화면 상태나 브라우저 저장소에만 의존하지 않는다.
  • 네트워크가 끊기면 저장되지 않음 상태를 명확히 표시하고 중복 저장/유실을 막는 재시도 정책을 둔다.

FR-11. 관리자 조회 및 조정 [P0]

  • 계정별 닉네임, 상태, 자음별 진행, 150개 음절별 숙달 여부를 조회한다.
  • 특정 음절을 미습득 ↔︎ 숙달로 보정할 수 있으며 보정 사유·수행자·시각을 남긴다.
  • 학습 기록 초기화는 별도 확인 절차를 거쳐야 한다.
  • CSV 내보내기는 P1 확장으로 둔다.

FR-12. 학습 통계·피드백 [P1]

  • 학생에게 오늘 익힌 음절, 전체 읽을 수 있는 음절 수, 다음 연습할 음절을 간단히 표시한다.
  • 관리자에게 음절별 오답 빈도·시도 횟수·마지막 학습일을 제공한다.
  • 학생 화면에서는 다른 학생과의 순위 비교를 제공하지 않는다.

7. 학습·평가 상태 모델

7.1 음절별 상태

  • not_started: 아직 학습하지 않음.
  • learning: 듣기·따라 쓰기를 진행했으나 읽기 정답 미확인.
  • needs_practice: 읽기 오답으로 재학습 필요.
  • mastered: 해당 음절의 읽기 평가를 통과함(기본 목록 제외).

traceCompleted(쓰기 활동 완료)는 위 읽기 숙달 상태와 분리하여 저장한다.

7.2 평가 알고리즘(기본안)

자음 선택
  → 학습 대상 음절 불러오기
  → 숙달(mastered) 음절 제외
  → 남은 음절 중 최대 5개 선정(오답 이력 우선, 이후 무작위)
  → 음절 1개 표시, 마이크 버튼으로 발화 평가
  → 정답: mastered 저장, 이후 기본 출제에서 제외
  → 오답: needs_practice 저장, 정답 음성 1회 제공, 재학습 권유
  → 인식 오류/권한 거부: 오답 저장하지 않고 재시도/교사 판정
  → 평가 종료 후 남은 미숙달 음절이 있으면 재학습·다음 평가
  → 해당 자음의 전체 목표 음절이 mastered이면 자음 ✓ 표시

7.3 판정 신뢰도 정책

  • 초기 기본안: 교사 확인 또는 충분히 검증된 자동 판정으로 정답을 인정하면 mastered 처리한다.
  • 자동 음성 인식이 기술적으로 불안정하면 자동 판정만으로 숙달 확정하지 않는 모드를 기본값으로 전환한다.
  • 장기 보존력 검사는 선택적 유지 확인 모드(P2)로 구현할 수 있으나, 유지 확인을 기본 반복학습과 구별하여 사용자의 정답 음절 제외 원칙을 해치지 않는다.

9. 권장 기술 구조

9.1 우선 기술 스택

  • 프런트엔드: HTML + CSS + TypeScript(JavaScript) + Vite. 필요하면 React를 도입하되 단순한 학습 흐름 구현이 우선이다.
  • 쓰기: HTML Canvas + Pointer Events; touch-action: none 등을 쓰기 캔버스에 한정 적용.
  • 음절 듣기: Hosting에 배포한 한국어 음절 음성 파일 재생.
  • 읽기 평가(1차 실험): Web Speech API SpeechRecognition(ko-KR), Android Chrome 실기기 검사.
  • 인증: Firebase Authentication.
  • 데이터: Cloud Firestore.
  • 정적 호스팅: Firebase Hosting, HTTPS.
  • 서버 기능: Spark 무료 요금제를 우선 유지하기 위해 Cloud Functions에 필수 의존하지 않는다. 관리자 권한 초기 설정은 신뢰 가능한 운영자 환경에서 수행한다.

9.2 무료 운영 전제

  • Firebase Spark 무료 플랜의 Hosting / Authentication / Firestore 사용량 한도 내에서 운영한다.
  • 공식 문서상 일반 Firestore 무료 할당량은 하루 문서 읽기 50,000회, 쓰기 20,000회이며, 사용량과 정책은 바뀔 수 있으므로 배포 전 재확인한다.
  • 오디오 파일은 재사용·캐시하여 Hosting 전송량을 줄인다.
  • 유료 음성 인식 API나 유료 서버가 필요하면 비용 재산정 후 별도로 승인한다.
  • 무료로 시작 가능이 곧 사용량 무제한·자동 발음 판정 품질 보장을 뜻하지는 않는다.

9.3 구현상의 중요 제약

  • 이메일/비밀번호 기반 회원가입은 Firebase Authentication으로 구현하기 쉽지만, 이메일 없이 닉네임/숫자 PIN만으로 로그인하려면 별도의 안전한 계정 매핑·인증 설계가 필요하다.
  • 웹 앱의 관리자 UI에서 다른 사용자 비밀번호를 직접 설정하거나 Firebase Auth 사용자를 일괄 삭제하려면 권한 있는 백엔드(Admin SDK)가 필요하다. MVP에서는 승인/상태/진도 관리와 공식 비밀번호 재설정 경로를 제공한다.
  • Android Chrome 음성 인식 지원 여부, 한글 단음절 판정 성능, 마이크 권한 정책은 실기기 테스트로 검증한다.

10. 데이터베이스 초안 (Cloud Firestore)

contentVersions/{versionId}
  version, status, syllableCount, publishedAt

syllables/{syllableId}
  char, onset, vowel, audioPath, guidePath,
  order, enabled, curriculumVersion

users/{uid}
  nickname, accountStatus, createdAt, lastActiveAt,
  curriculumVersion, settings { audioMode, replayIntervalMs, tracingMode }

users/{uid}/syllableProgress/{syllableId}
  status, studyCount, traceCompleteCount,
  correctCount, wrongCount, lastStudiedAt,
  lastEvaluatedAt, masteredAt, updatedAt

users/{uid}/assessmentSessions/{sessionId}
  consonant, questionSyllableIds, answers,
  status, startedAt, completedAt, curriculumVersion

adminAuditLogs/{logId}
  actorUid, targetUid, action, before, after, reason, createdAt
  • 관리자 권한은 Firestore 사용자가 자기 프로필에 써 넣은 role 문자열을 신뢰하지 않고, 관리자 SDK로 설정한 인증 토큰의 custom claim 또는 동등한 서버 검증 방식으로 판단한다.
  • 보안 규칙은 기본 거부 후 자기 자료만 읽기/쓰기 허용하고 관리자에게만 교차 열람·관리 권한을 부여한다.
  • 가입 pending 상태 사용자의 학습 데이터 접근을 차단한다. 계정 상태를 학생 스스로 active로 수정하지 못하도록 규칙을 분리한다.
  • 학습자 ID 변경, 커리큘럼 개정, 기록 초기화는 이력/마이그레이션 정책을 적용한다.

11. 개인정보 및 학교 현장 운영 원칙

  • 학생 실명, 장애 유형·정도, 학교명, 생년월일, 사진, 위치정보를 원칙적으로 요구하지 않는다.
  • 음성 인식이 외부 음성 처리 서버에 연결되는 경우, 학생의 음성이 제3자 서비스에 전송될 수 있다. 실제 구현 서비스의 데이터 흐름을 확인하고 안내·법적 근거를 정비한다.
  • 음성 파일 및 쓰기 원본은 기본 저장하지 않고, 읽기 판정 결과·학습 이벤트만 최소한으로 저장한다.
  • 만 14세 미만 학생의 개인정보 처리를 동의를 근거로 수행한다면, 개인정보 보호법에 따른 법정대리인의 동의와 확인 절차가 필요하다. 학교 교육활동으로 처리할 경우 적용 법적 근거·교육청/학교 지침은 별도 검토한다.
  • 개인정보 처리방침, 보유 기간, 계정 탈퇴·기록 삭제, 관리자 접근 권한, 유출 대응 절차를 배포 전 마련한다.
  • 장애 관련 민감 정보는 수집하지 않는 것을 기본으로 한다.

12. 개발 우선순위·로드맵

단계범위완료 기준
M0. 콘텐츠·기술 검증150개 음절 선정 기준, 일부 음성 파일 샘플, Android Chrome 음성 인식·필기 PoC단음절 인식 가능성과 기술적 위험 확인
M1. 학습 웹 MVP로그인·승인, 닉네임, 자음 메뉴, 1회 듣기, 따라 쓰기, 개인별 DB 저장기기를 바꿔도 진도 복원 가능
M2. 평가 및 재학습5문항 평가, 정답 제외, 오답 재학습, 자음 ✓, 교사 수동 판정150개 음절별 숙달 상태 오류 없이 관리
M3. 음성 자동판정 실험마이크, ko-KR 음성 인식, 판정 오류 처리, 수동 보정실기기 테스트 결과에 따라 자동판정 사용 여부 결정
M4. 관리자·출시계정 관리, 현황 조회, 권한 규칙, 개인정보 안내, 오류 대응파일럿 운영 준비 완료
P2. 향후 확장종성 학습, 주기적 유지 확인, 교사별 학생 그룹, 통계 개선교육 효과 검증 후 진행

중요: M3 자동판정이 기준에 미달하더라도 교사 수동 판정이 가능한 읽기 평가 중심 MVP를 먼저 완성한다. 자동 인식이 개발 전체의 병목이 되지 않도록 기능을 분리한다.

14. 출시 전 검증 계획

  1. 교육 콘텐츠 검토: 특수교사에게 150개 선정 기준·발음 음성·학습 순서 검토를 받는다.
  2. 필기 테스트: 손가락/S펜, 손바닥 접촉, 획 순서 차이, 필기 불안정성을 시험하고 오판 시 우회 가능한지 확인한다.
  3. 발음 테스트: 실제 안드로이드 태블릿 Chrome에서 여러 음절(유사 음절 포함)의 인식률, 오인식률, 권한 및 네트워크 오류를 기록한다.
  4. 교육적 판단: 발화 특성으로 인한 불공정 오답이 빈번하면 자동판정을 기본에서 제외한다.
  5. 계정·DB 테스트: 다른 학생 데이터 열람 불가, 관리자 승인 우회 불가, 재로그인 시 기록 유지.
  6. 소규모 파일럿: 적절한 승인과 개인정보 보호 조치 후 교사가 관찰하며 실제 학생 사용성을 확인한다.

15. 최종 의사결정이 필요한 항목

  1. 150개 음절 확정: 실제 말뭉치 빈도 + 교사 검토를 거친 최종 목록.
  2. 자음 메뉴 범위: 기본 자음 14개만 사용할지, 쌍자음 5개도 포함할지.
  3. 완료 기준: 원안의 무작위 5개 모두 맞히면 자음 완료 대신 이 PRD 추천안인 해당 자음 모든 음절 숙달 시 완료 승인 여부.
  4. 읽기 숙달 판정: 한 번의 정답으로 확정할지, 교사 확인 또는 누적 정답을 추가할지.
  5. 로그인 절차: 학생이 직접 이메일/비밀번호를 사용하는지, 교사 지원 계정을 만드는지, 향후 쉬운 ID/PIN을 별도 개발할지.
  6. 음성 자동판정 허용: Android Chrome 한 음절 인식 실험 후 자동판정 사용 범위 결정.
  7. 필기 통과 방식: 따라 쓰기 판정 엄격도 및 운동·필기 어려움 학생을 위한 생략 정책.

개발 원칙 최종 요약: 특수교육대상학생에게 150개 개음절을 통문자 방식으로 가르치되, 학습 목표는 따라 쓰기가 아니라 스스로 읽기이다. 결과를 학생별로 누적 저장하고, 이미 읽는 음절은 기본 반복에서 제외, 아직 읽지 못하는 음절에 가장 많은 시간을 배분한다.
