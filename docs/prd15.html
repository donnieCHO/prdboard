PRD: 소리나라 v1 — 초등 음악 수업용 학생 태블릿 앱 + 교사 대시보드

화면 모양·색·글꼴 같은 세부는 디자인 시안(student-daw-design.html)과 design-tokens.json이 기준이다. 이 문서는 "무엇을, 왜" 만드는지만 적는다.

문제

  • 초등 3~6학년 "디지털 음악 만들기" 단원은 iPad 개러지밴드를 전제로 하지만, 교실 태블릿은 안드로이드가 많다. 안드로이드에는 아이들이 쓸 무료 음악 만들기 앱이 마땅치 않다.
  • 개러지밴드는 성인용이라 메뉴·영어·설명이 많아 수업 시간 안에 쓰기 어렵다.
  • 선생님은 30명이 연주할 때 누가 얼마나 연습했는지 볼 수 없고, 동시에 시작시키거나 합주를 들려줄 방법도 없다.
  • 장구·세마치장단은 교과서에 나오지만, 태블릿으로 치고 맞았는지 확인할 앱이 거의 없다.

해결

소리나라 = 학생용 태블릿 앱(안드로이드·iPad, 가로 전용, 크롬북은 안드로이드 앱) + PC 브라우저용 교사 대시보드.

주 목적 두 가지: ① 디지털 기기로 연주하기 ② 디지털 음악 만들기. 같이 연주하기(점수)와 교사 대시보드는 이 둘을 돕는 기능이다. 우선순위도 이 순서를 따른다.

학생 메뉴 세 개가 곧 단계다. 앞 단계의 악기·소리·계이름 색이 다음 단계 재료로 그대로 이어진다.

단계메뉴하는 일
1악기 연주하기디지털 악기를 자유롭게 쳐 본다
2같이 연주하기곡에 맞춰 연습하고 점수를 받는다
3노래 만들기연주해 본 악기로 노래를 만든다

지킬 원칙

  • 화면에 설명 문구를 두지 않는다. 뜻은 아이콘·라벨·배치·색으로 전한다. 알림은 2~4단어.
  • 모든 소리는 실제 악기 녹음이고, 누르는 순간 바로 난다.
  • 소리는 각 태블릿에서 낸다. 네트워크로는 시작 신호·진행·점수만 오간다.

사용자 이야기

들어오기

  1. 학생은 선생님이 알려 준 6자리 수업 코드만으로 들어간다. 들어가면 내 반·번호가 보인다.
  2. 학생은 수업 코드가 없는 날에도 학교 계정으로 로그인해 내 노래를 연다.
  3. 선생님은 계정 로그인으로 대시보드에 바로 간다.

메뉴

  1. 학생은 첫 화면에서 악기 연주하기 · 같이 연주하기 · 노래 만들기 세 가지만 보고, 글을 읽지 않고 그림·색으로 고른다.
  2. 학생은 어느 화면에서든 뒤로 버튼으로 돌아간다.

악기 연주하기

  1. 학생은 악기 6개(피아노·실로폰·리코더·단소·기타 | 장구)를 한눈에 보고, 고를 때 그 소리를 미리 듣는다.
  2. 학생은 피아노·기타를 계이름 색 건반으로 친다. 계이름 표시를 켜고 끄고, 옥타브를 바꾸고, 화음을 낸다.
  3. 학생은 실로폰을 계이름 색 막대로 보고, 칠 때마다 채가 막대를 때리는 모습을 본다.
  4. 학생은 리코더·단소의 음 단추를 누르면 그 음의 운지(막는 구멍·여는 구멍, 뒷구멍 포함)를 보고 소리를 듣는다. 리코더는 저먼식·바로크식을 고르고, 단소는 중·임·무·황·태로 본다.
  5. 학생은 장구 궁편·채편을 따로 쳐서 연주한다. 덩 버튼 없이 두 편을 같이 치면 덩, 채편을 빠르게 두 번 치면 기덕이 되고, 친 소리 이름이 크게 보인다.
  6. 학생은 세마치장단 안내를 보며 치고 칸마다 맞음·틀림을 바로 본다. 시범 연주와 예비박을 먼저 듣는다.
  7. 학생은 자유 연주에서 친 음이 바로 오선 악보에 그려지는 것을 본다.

같이 연주하기

  1. 학생은 선생님이 정한 오늘의 수업 곡과 마감일을 먼저 본다.
  2. 학생은 곡을 제목이나 초성(예: ㄴㅂㅇ)으로 찾고, 곡마다 첫 두 마디 악보를 미리 본다.
  3. 학생은 실제 오선 악보를 한 줄씩 보며 음원 박자에 맞춰 친다. 악보 아래 계이름이 보이고, 다음에 칠 건반이 반짝인다.
  4. 학생은 칠 때마다 정확·좋아·놓침을 바로 보고, 끝나면 100점 만점 점수와 별, 내 최고 점수를 본다.
  5. 학생은 "기다려 주기" 모드와 속도 조절로 어려운 곡을 천천히 연습한다.
  6. 학생은 시작할 때 곡 빠르기로 한 마디 예비박을 듣는다.
  7. 학생은 선생님이 허락하면 악보 대신 떨어지는 계이름 색 음표(리듬게임)로 연습한다.
  8. 학생은 합주곡에서 파트(가락·반주·장구·탬버린 등)와 악기를 골라 연주하고, 내가 맡지 않은 파트는 앱이 들려준다. 타악기 파트는 큰 패드와 칸 악보로 친다.
  9. 학생은 선생님이 다같이 연주를 열면 대기 화면에서 파트를 고르고, 선생님이 시작하면 반 전체와 같은 순간에 시작한다. 이때 앱은 다른 파트를 대신 연주하지 않는다.

노래 만들기

  1. 처음 들어온 학생은 따라 하기만 하면 되는 튜토리얼(박자 고르기 → 리듬 찍기 → 상자에 담기 → 노래에 넣기 → 들어 보기)을 한다. 만든 리듬은 첫 작품으로 남는다. 다음부터는 바로 만들기 화면이 나오고, 원하면 튜토리얼을 다시 본다.
  2. 학생은 고른 박자에 맞게 나뉜 칸을 눌러 리듬을 만들고, 그 리듬이 ♩(타)·♫(티티)·쉼 악보로 바로 보이는 것을 본다.
  3. 학생은 만든 리듬을 상자에 담고, 상자의 리듬을 내 노래 칸에 놓거나 뺀다(끌어다 놓기 없이 누르기만으로).
  4. 학생은 여러 악기 트랙(가락·리듬·장구·목소리 녹음 등)을 쌓고, 마디를 자르기·복사·반복·지우기 하고, 트랙마다 음소거한다. 트랙 악기는 악기 연주하기에서 본 것과 같은 사진·이름·소리다.
  5. 학생은 내 노래를 재생하며 지금 위치를 보고, 빠르기·박자를 바꾼다.
  6. 학생은 내 노래 목록을 보고 새로 만들거나 이름을 바꾼다. 저장 버튼 없이도 기기에 남는다.

AI 창작 도움

  1. 학생은 막혔을 때 이어질 가락이나 어울리는 리듬·반주 제안을 받아 들어 보고, 마음에 들 때만 넣고 넣은 뒤에도 고친다. 제안은 내가 만든 것과 같은 방식(계이름 색 음표·리듬 악보)으로 보인다.
  2. 선생님은 AI 제안을 반 단위로 켜고 끄고, 학생 작품에서 AI가 넣은 부분을 구분해 본다.

교사

  1. 선생님은 오늘의 수업 곡과 마감일을 곡 목록에서 골라 바로 바꾼다.
  2. 선생님은 학생 30명을 한 화면 칸으로 보고, 칸마다 연습 횟수·최고·최근 점수, 연주 중 여부, 지금 단계를 실시간으로 본다.
  3. 선생님은 학생 칸을 눌러 그 학생의 연습 기록을 보고, 전체·연주 중·미연습·60점 미만으로 걸러 본다.
  4. 선생님은 수업 전체 요약(연주 중 수, 연습한 학생 수, 평균 최고점, 총 연습 횟수)을 본다.
  5. 선생님은 점수표를 정렬하고 내려받는다.
  6. 선생님은 다같이 연주 화면에서 준비된 학생과 파트별 인원을 보고, 시작·멈춤을 누른다. 시작하면 내 기기도 예비박과 진행을 교실 스피커·화면으로 낸다.
  7. 선생님은 합주 때 학생들이 치는 음을 교실 스피커로 모아 듣는다.
  8. 선생님은 반이나 학생별로 열어 줄 단계와 떨어지는 음표 허용 여부를 정한다.
  9. 선생님은 직접 곡(음원·악보)을 넣는다.
  10. 선생님은 따로 앱 설치 없이 PC 브라우저에서 대시보드를 연다.

공통

  1. 학생의 연주와 점수는 와이파이가 끊겨도 남고, 다시 연결되면 저절로 올라간다.
  2. 학부모는 아이 이름·점수가 어디에 얼마나 보관되는지 알고 동의한다.
  3. 학교는 앱 "출처" 화면에서 사진·음원·글꼴 출처를 확인한다.

구현 결정

앱 구성

  • 학생 앱: Flutter 하나로 안드로이드·iPad·크롬북. 가로 고정, 기준 1280×800dp, 반응형(4:3 아이패드~휴대폰 가로). 누르는 곳은 44 이상.
  • 소리: C++ 오디오 엔진(miniaudio 또는 JUCE, 안드로이드 AAudio/Oboe, iOS Core Audio). 웹 오디오는 지연 때문에 쓰지 않는다(시안의 웹 오디오는 시안 전용).
  • 교사 대시보드: PC 웹(React 등) 또는 Flutter Web. 학생 앱과 같은 실시간 DB(Firestore 또는 Supabase).

모듈

  • 소리 엔진: "악기·음 높이(MIDI)·세기·시각" 이벤트를 받아 기기에서 바로 소리를 낸다. 가장 가까운 음원을 골라 재생 속도로 음 높이를 맞춘다. 실로폰·소프라노 리코더는 한 옥타브 위로 낸다. 이벤트 목록을 오프라인으로 렌더해 테스트할 수 있어야 한다.
  • 연주 판정: 순수 로직. 기대 음 타임라인 + 학생 입력 → 음마다 판정과 점수.
    • 정확 ±0.1초, 좋아 ±0.25초, 그 밖은 놓침. 100점 만점.
    • 기다려 주기: 맞는 음이 나올 때까지 진행 시계를 멈춘다.
    • 장구: 궁+채 0.08초 안 = 덩, 채+채 0.18초 안 = 기덕, 궁만 = 쿵, 채만 = 덕. 세마치 9칸 판정 ±0.17초.
  • 수업 데이터: 기기에 먼저 저장하고 서버로 동기화(local-first). 학생 기록(회차·점수·시각·곡·튜토리얼 완료), 교사 데이터(오늘의 곡·마감·반·학생 번호·열린 단계·떨어지는 음표 허용), 대시보드 집계.
  • 곡 데이터: 박자 + 여러 파트(이름, 건반/장구/타악기, 반주 악기, 음표 목록). 학생이 고른 파트만 판정하고 나머지는 같은 시계로 앱이 연주한다.
    • v1 곡 6개: 작은 별, 비행기, 나비야, 퐁당퐁당, 환희의 송가(4파트), 아리랑(장구 세마치 포함). 가락만, 가사 없음.
  • 노래 만들기: 리듬 한 개 = 한 마디, 내 노래 = 마디 칸 목록. 재생은 이 목록을 소리 엔진 이벤트로 바꿔서 한다.
  • AI 창작 도움: 만든 노래 데이터를 받아 같은 형식의 제안을 돌려주는 모듈. AI 허브 음악 데이터로 학습. 넣은 부분에 "AI 제안" 출처 표시.
  • 곡·장단·악기 목록과 디자인 색은 코드가 아니라 데이터 파일(JSON)로 둔다.

30명 동시 사용

  • 동시 시작: 서버 시각을 맞춘 뒤 "N초 뒤 시작" 예약.
  • 합주: 학생 기기 → 교사 기기로 음 이벤트 전송, 교사 기기가 약 100ms 버퍼 후 교실 스피커로 재생.

라이선스

  • 서양 악기 음원은 CC0(VCSL, VSCO 2 CE, FreePats), 국악기는 국립국악원(공공누리 제1유형).
  • 사진은 CC BY/BY-SA·퍼블릭 도메인·공공누리, 앱 "출처" 화면에 표시. 글꼴은 OFL 전문 포함.
  • 교과서 수록곡은 통째로 넣지 않는다. 저작권 끝난 곡 → 교사가 넣는 곡 → 출판사·KOMCA 제휴 순.

개인정보: 만 14세 미만이라 법정대리인 동의. 보관 기간을 정하고 학교·교육청 지침을 따른다. 서버엔 이름 대신 번호만 두는 방식을 검토한다.

테스트

겉으로 드러나는 동작(입력 → 결과)만 확인한다. 시간 판정은 주입한 시각으로 확인한다.

  1. 소리 엔진(가장 우선): 이벤트 목록 → 오프라인 렌더 → 소리 시작 시각·음 높이 확인. 가까운 음원 선택, +12 옥타브, 화음, 음원 없음, 만든 노래 렌더.
  2. 연주 판정: 0.1·0.25초 경계, 빠름/늦음/안 침/엉뚱한 음, 기다려 주기, 속도 변경. 장구 0.08·0.18초 안팎, 세마치 ±0.17초.
  3. 수업 데이터(가짜 서버): 오프라인 저장 → 재연결 → 서버 반영, 집계 정확도, 중복 방지.

동작 견본은 HTML 시안이다.

범위 밖 (v1)

  • 세마치 밖의 장단(굿거리·자진모리·중모리)
  • 드럼 연주 화면(시안에만 남김), 소고(음원 없음), 꽹과리·징
  • 교과서 수록곡 일괄 탑재, 곡 판매·결제
  • 휴대폰·세로 화면, 학생 앱 웹 버전
  • 학생끼리 공유·댓글

정할 것·확인할 것

  • 오디오 엔진(miniaudio 대 JUCE), 실시간 DB(Firestore 대 Supabase)
