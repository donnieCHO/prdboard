배움노트 학습관리 웹앱 — 제품 요구사항 정의서(PRD)

0. 한눈에 보는 제품

항목내용
한 줄 소개학생은 시간표·할 일·수행평가·공지를 한곳에서 챙기고, 교사는 수업 중 기록을 생기부 종합의견으로 이어 쓰며, 관리자는 시간표·권한·디자인을 학교에 맞게 운영하는 학교 단위 학습관리 웹앱
쓰는 사람초·중·고 학생, 교사(수업계 담당 교사 포함), 학교 관리자
핵심 흐름학생: 로그인 → 반 시간표·과목 공지 → 과목플랜 할 일 체크 → 수행평가 제출 → 주간 완료 시 몬스터 획득
교사: 수업 일정 → 교시별 학생 기록 → 기간별 기록 모으기 → AI 다듬기·바이트 검사 → 나이스용 복사
교사 입구같은 웹앱의 교사 탭: 수업 일정, 학생관리, 학생종합의견, 수행평가, 공지, 자료 내보내기, 수업 교체
기기학생 휴대폰·태블릿, 교사 PC, 교실 대형 화면. PWA(홈 화면 추가)
서버가 남기는 것사용자(이름·학년·반·번호·담당 과목), 시간표, 할 일, 수행평가와 제출 파일, 공지, 수업현황 기록(출결·행동특성), 종합의견, 수업 교체 신청, 민감 자료 변경 기록

0.1 화면 문구 지침

  • 한국어 존댓말로 짧게 쓴다. 「업로드 실패」 대신 「파일이 20MB를 넘어요」처럼 까닭을 말한다.
  • 막힐 때는 무엇을 하면 되는지 한 문장으로 말한다(예: 「오늘 호출 한도를 넘었어요. 내일 다시 시도하세요」).
  • 되돌릴 수 없는 일(모두 지우기, 비밀번호 초기화)은 한 번 더 묻는다.
  • AI가 만든 문장에는 늘 「사실과 다른 내용이 없는지 꼭 확인」을 붙인다.
  • 용어: 교사의 교시별 기록은 「수업현황 기록」, 생기부 문장은 「학생종합의견」, 학생 할 일 목록은 「과목플랜」, 공지 없이 보내는 과제는 「자유 제출」로 부른다.

1. 문제 정의와 교육적 근거

1.1 해결하려는 문제

  • 과목별 과제·마감·공지가 메신저·종이로 흩어져 학생이 놓친다.
  • 수업 중 관찰한 내용이 학기말까지 남지 않아 종합의견을 기억에 기대어 쓴다.
  • 생기부 문장 다듬기, 나이스 바이트 계산, 맞춤법 검사에 교사 시간이 많이 든다.
  • 수행평가 지각 감점 계산과 제출물 정리가 수작업이다.
  • 수업 교체(맞교체·대강·보강) 신청·승인·학생 안내가 따로 놀아 학생이 바뀐 수업을 모른다.
  • 학교마다 시간표 양식이 달라 새 도구를 들일 때마다 입력이 번거롭다.

1.2 교수·학습 가설

  • 시간표·할 일·마감을 한 화면에서 보면 학생이 스스로 계획을 세우고 지킨다.
  • 주 단위로 할 일을 끝내면 과목 몬스터를 모으는 작은 보상이 꾸준한 실천을 돕는다.
  • 교사가 수업 직후 짧게 남긴 관찰 기록이 쌓이면 종합의견이 구체적이고 사실에 가까워진다.
  • AI는 교사 기록만 근거로 문장을 다듬고, 최종 판단은 교사가 한다.

1.3 제품 원칙(우선순위 순)

  1. 학생 개인정보를 지킨다. 역할별로만 보이게 하고(행 단위 권한), AI에는 학생 이름을 가려 보낸다.
  2. 교사 기록이 근거다. AI 문장은 교사의 관찰 기록과 초안만 근거로 만들고, 교사가 확인·수정한다.
  3. 한 흐름으로 잇는다. 수업 기록 → 종합의견, 교체 신청 → 승인 → 시간표 → 학생 알림이 끊기지 않는다.
  4. 학교에 맞춘다. 시간표 가져오기, 기능 켜고 끄기, 메뉴·색·로고를 관리자가 정한다.
  5. 한 학교 한 배포본. 학교마다 따로 배포해 데이터가 섞이지 않는다.

2. 사용자

2.1 1차 사용자

초·중·고 교사와 학생. 교사는 수업 기록과 종합의견 작성 시간을 줄이길 원하고, 학생은 과목별 할 일과 마감을 놓치지 않길 원한다.

2.2 사용자 유형

유형들어가는 법할 수 있는 것
학생학생 탭 → 아이디(지금: s+학년도 2자리+학번 4자리, 예 s261101) + 비밀번호반 시간표·공지 보기, 과목플랜, 내 과목 관리, 수행평가·자유 제출, 몬스터함
교사교사 탭 → 관리자가 발급한 아이디 + 비밀번호수업 일정·진도, 학생 기록, 종합의견, 수행평가 관리·채점, 공지, 자료 내보내기, 수업 교체 신청, 생기부 규칙 설정
수업계 담당 교사교사와 같음(관리자가 지정, 여러 명 가능)교사 기능 + 수업 교체 승인·반려
관리자관리자 탭 → 관리자 비밀번호사용자 등록, 과목·시간표 관리, 교사 업무, 기능 권한, 사용자로 보기, 데이터 관리, 화면 디자인, 보안 설정
  • 다른 탭 계정으로 로그인하면 올바른 탭을 안내한다.
  • 첫 로그인·초기화 뒤에는 새 비밀번호(8자 이상)로 바꿔야 쓸 수 있다.

5.3 UI·접근성 원칙

  • 휴대폰부터 교실 대형 화면까지 한 화면 구성으로 맞춘다.
  • 글자 크기를 관리자가 키울 수 있다(교실 화면용).
  • 대표색·포인트색을 바꿔도 글자색은 자동으로 대비를 맞춘다.
  • 메뉴 순서·이름·보이기를 학교가 정한다.
  • 일정 시간(기본 30분) 쓰지 않으면 자동 로그아웃한다.

6. 기능 요구사항

표시: ✅ 배포됨 · 🔜 결정됐지만 개발 전

FR-01. 로그인과 비밀번호 [P0] ✅

  • 학생·교사·관리자 탭으로 로그인한다. 다른 탭 계정이면 올바른 탭을 안내한다.
  • 첫 로그인·초기화 뒤에는 8자 이상 새 비밀번호로 바꿔야 계속 쓴다.
  • 스스로 비밀번호를 바꿀 때는 현재 비밀번호를 확인한다.
  • 오래 쓰지 않으면 자동 로그아웃하고 그 까닭을 알린다.

FR-02. 학생 첫 화면 [P0] ✅

  • 우리 반 이번 주 시간표를 보이고, 교체·변경된 수업을 표시한다.
  • 과목 공지 알림을 함께 보인다. 수업 전 긴급 공지는 맨 위 띠로 보이고 「확인했어요」로 닫는다.

FR-03. 과목플랜 [P0] ✅

  • 과목·할 일·마감일로 할 일을 추가하고 체크한다. 완료 숨기기, 남은 개수를 보인다.
  • 학교 과목 외에 나만의 과목을 추가·수정·삭제한다(관리자가 끌 수 있음).

FR-04. 몬스터함 [P1] ✅ / 🔜

  • 과목별 이번 주 마감 할 일을 모두 체크하면 그 과목 몬스터가 들어온다.
  • 이번 주 몬스터 진행도와 모은 몬스터 수를 보인다.
  • 학년에 따라 아기·성장·완전체로 보인다.
  • 🔜 학교급 설정에 따라 성장 단계를 나눈다(초등 6개 학년).

FR-05. 수행평가 제출 [P0] ✅

  • 우리 반에 공개된 수행평가를 고르면 공지·교사 자료·제출 창이 열린다.
  • 제출 기간 밖에는 제출할 수 없다. 지각 허용 과제는 「지금 제출하면 N일 지각 · X% 감점」을 미리 보인다.
  • 제출 회수·다시 제출, 점수와 피드백 확인.
  • 자유 제출: 공지된 과제 없이 교사를 골라 제목·메모·파일을 보내고 승인을 요청한다.
  • 파일은 20MB까지.

FR-06. 수업 일정 [P0] ✅

  • 월 달력과 내 주간 시간표. 날짜를 누르면 그날 수업, 진도 기록, 수행평가 마감, 수업 변경, 공지를 보인다.
  • 교시마다 할 일·진도를 저장하고, 수업 전 공지 보내기·수업 교체 신청으로 바로 간다.

FR-07. 학생관리(수업현황 기록) [P0] ✅ / 🔜

  • 수업(교시·반)을 고르면 학생 목록이 열리고, 학생마다 출결·행동특성·수업 및 발표 내용·특이사항을 기록한다.
  • 「모두 출석」「전체 저장」. 빈 칸은 저장하지 않는다.
  • 🔜 지각·조퇴·결과도 나이스처럼 질병/미인정/기타로 나눈다.
  • 🔜 담임이 반 출결을 최종 확정한다.

FR-08. 학생종합의견 [P0] ✅

  • 학생과 기간을 고르면 그 기간 수업현황 기록과 출결 요약이 모인다(내 기록만 / 모든 교사 기록).
  • 넘길 기록을 체크해 초안으로 불러온다.
  • AI로 생기부형 한 문단을 만든다. 근거는 교사 기록과 초안뿐이고, 학생 이름은 가려 보낸다. 바이트 한도를 넘으면 경고한다.
  • 오타 검사(규칙 기반, 즉시)와 맞춤법 정밀 검사(AI): 고칠 곳/확인할 곳, 하나씩·모두 고치기.
  • 나이스 바이트(한글 3, 영문·숫자·공백 1, 줄바꿈 2)를 실시간 표시하고 「나이스용 복사」·저장.

FR-09. 생기부 작성 규칙 [P1] ✅

  • 교사 설정: 문체(담백·따뜻·역량 중심), 바이트 한도, 나만의 규칙, 금지어, 문체 참고 예시.
  • 학교 공통 규칙(관리자)과 합쳐 AI에 전달하고 미리보기로 보인다. 금지어는 오타 검사에서도 잡는다.

FR-10. 수행평가 관리·채점 [P0] ✅

  • 등록·수정: 과목, 대상 반, 공지, 제출 시작·마감, 마감 후 제출 허용(하루 감점 %, 최대 감점 %, 지각 마지막 날), 만점, 평가 자료, 「학생 공지사항에도 올리기」.
  • 채점표: 학생별 제출물, 지각 일수·감점 자동 계산, 원점수 → 승인 / 반려(재제출 가능), 피드백.
  • 자유 제출함에서 요청을 승인·반려한다.

FR-11. 공지 [P0] ✅

  • 대상 반·과목, 연결 수행평가, 첨부를 넣어 공지를 쓰고 고친다.
  • 「수업 전 긴급 공지」는 학생 화면 맨 위 띠로 보인다.

FR-12. 수업 교체 신청 [P0] ✅

  • 맞교체·대강·보강·정규 시간표 변경을 신청한다.
  • 검증: 내 정규 수업이 있는 시간인지, 옮길 시간에 이미 내 수업이 있는지, 상대 교사가 그 시간에 수업이 있는지.
  • 사유는 수업계·관리자만 보고 학생 공지에는 넣지 않는다. 신청을 취소할 수 있다.
  • 내 시간표에서 「시간표 변경 요청」을 보낸다.

FR-13. 교체 승인 [P0] ✅

  • 수업계 담당 교사에게만 보인다. 도착한 신청 개수를 표시한다.
  • 학생 공지 문구를 확인·수정한 뒤 승인하면 시간표·수업 일정에 반영하고 해당 반 학생에게 수업 전 알림을 보낸다.
  • 반려할 때는 사유를 꼭 쓴다.

FR-14. 자료 내보내기 [P1] ✅

  • 학생명단·수업현황(행동특성)·출결요약·종합의견 4개 시트를 .xlsx로 내려받는다.
  • 구글 시트 붙여넣기용 복사, 수업현황만 CSV. 학생 비밀번호는 넣지 않는다.

FR-15. 사용자·과목 관리 [P0] ✅

  • 학교 이름 변경. 학생(이름·학년·반·번호·아이디)과 교사(이름·담당 과목)를 한 명씩 또는 여러 줄로 등록한다. 중복·형식 오류 줄은 건너뛰고 알린다.
  • 검색, 비밀번호 초기화, 삭제.
  • 학교 과목 추가, 과목별 몬스터 고르기, 기본 과목 한 번에 만들기.

FR-16. 시간표 관리 [P0] ✅

  • 나이스 가져오기: 학교급·교육청 코드·학교 코드·학년도·학기(또는 한 주) → 반·요일·교시마다 가장 많이 나온 과목을 정규 시간표로 저장. 서버 인증키 또는 직접 붙여넣기. 오류 코드별 안내.
  • 파일 올리기: 교사별 격자 / 반별 격자 / 목록형 / 나이스 파일 모양을 자동 인식(엑셀·CSV·PDF·HWPX). 교사별 양식 내려받기.
  • 선생님별 시간표: 과목·맡은 반을 고르면 자동 생성, 칸별 수정. 승인된 시간표 변경 목록.
  • 운영 설정: 하루 교시 수, 종합의견 바이트 한도 기본값(1500), 학교 공통 생기부 규칙.

FR-17. 교사 업무 [P1] ✅ / 🔜

  • 교사별 업무 메모, 수업계 담당 지정(여러 명).
  • 🔜 반별 담임 지정(출결 확정 권한).

FR-18. 기능 권한과 사용자로 보기 [P1] ✅

  • 학생 기능(첫 화면, 과목플랜, 수행평가 제출, 몬스터함, 나만의 과목), 교사 기능(수업 일정, 학생관리, 종합의견, 오타 검사기, 수행평가, 공지, 자료 내보내기, 수업 교체), AI(다듬기·정밀 검사)를 하나씩 켜고 끈다.
  • 특정 학생·교사 화면을 모든 권한으로 열어 확인·수정·삭제한다. 화면 위에 「관리자 보기 모드」를 표시한다.

FR-19. 데이터 관리 [P1] ✅

  • 항목별 저장 개수 보기, 모두 지우기(되돌릴 수 없음 확인).
  • 시연용 데모 데이터(가상 교사 2명·학생 6명·시간표·수행평가·공지·기록·할 일).
  • 전체 백업 복사·복원(관리자 비밀번호 제외).
  • 민감 자료 변경 기록(최근 300건).

FR-20. 화면 디자인·보안 설정 [P1] ✅

  • 학교 색 프리셋, 대표색·포인트색, 글자 크기, 로고(정사각형 자동 축소), 서비스 이름·환영 문구, 학생·교사 메뉴 순서·이름·보이기.
  • 관리자 비밀번호 변경.

FR-21. 학교급 설정 [P0] 🔜

  • 초·중·고 중 하나를 고르면 학년 수, 몬스터 성장 단계, 종합의견 바이트 한도 기본값, 기본 과목 목록이 바뀐다. 관리자가 다시 바꿀 수 있다.

FR-22. 새 학년도 진급과 고정 아이디 [P0] 🔜

  • 학생 아이디를 s+입학년도 2자리+학적번호로 고정한다. 관리자가 학적번호를 넣는다. 학년·반·번호는 따로 저장한다.
  • 학년도가 바뀌면 학년·반·번호를 한꺼번에 바꾼다(붙여넣기 또는 파일). 아이디와 데이터는 이어 간다.
  • 마지막 학년은 「졸업」으로 표시하고 로그인을 막는다.

FR-23. AI 사용 한도 [P2] 🔜

  • 기본은 한도 없음. 관리자가 켜면 교사마다 하루 사용 횟수(다듬기 + 정밀 검사 합산)를 제한한다.
  • 관리자는 교사별 사용량을 본다.

7. 상태 모델

7.1 계정

(관리자가 등록) → 임시 비밀번호 ──첫 로그인에서 8자 이상으로 변경──► 사용 중
사용 중 ──관리자가 초기화──► 임시 비밀번호
사용 중 ──관리자가 삭제──► (삭제)
🔜 사용 중(학생) ──마지막 학년에서 진급 처리──► 졸업(로그인 불가)

7.2 수행평가 제출

미제출 ──제출(기간 안 / 지각 허용 기간)──► 승인 대기
승인 대기 ──학생이 회수──► 미제출
승인 대기 ──교사 승인(점수·피드백)──► 승인 완료
승인 대기 ──교사 반려──► 반려 ──다시 제출──► 승인 대기
자유 제출: 요청 ──승인──► 승인 완료 / ──반려──► 반려

7.3 수업 교체

신청(대기) ──교사가 취소──► (취소)
신청(대기) ──수업계 승인──► 승인 → 시간표·수업 일정 반영 + 해당 반 학생 수업 전 알림
신청(대기) ──수업계 반려(사유 필수)──► 반려

7.4 학생종합의견

기록 모으기 → 초안 ──AI 다듬기──► 다듬은 문장(한도 넘으면 경고)
다듬은 문장 ──오타·맞춤법 검사·교사 수정──► 저장 ──나이스용 복사──► (나이스에 교사가 붙여넣음)

7.5 몬스터

이번 주 과목 할 일 일부 완료 ──남은 할 일 모두 체크──► 그 과목 몬스터 획득
학년이 오르면 단계가 바뀜: 아기 → 성장 → 완전체

11. 개인정보와 학교 현장 운영 원칙

  • 학생 정보는 이름·학년·반·번호·아이디만 받는다. 생년월일·연락처는 받지 않는다.
  • 수업현황 기록과 종합의견은 교사·관리자만 본다. 학생은 자기 제출물·점수·피드백만 본다.
  • AI에는 교사 기록과 초안만 보내고 학생 이름은 가린다. AI 문장은 교사가 확인한 뒤에만 쓴다.
  • 수업 교체 사유는 수업계·관리자만 본다.
  • 공용 기기에서는 다 쓴 뒤 로그아웃하도록 로그인 화면에서 안내하고, 오래 쓰지 않으면 자동 로그아웃한다.
  • 「사용자로 보기」는 관리자만 쓰고 화면에 표시가 남는다. 민감 자료 변경은 기록된다.
  • 데이터 보관 기간은 정하지 않는다. 관리자가 데이터 관리에서 지운다(자동 삭제 없음).

13. 수용 기준

  • 첫 로그인한 사용자는 새 비밀번호를 정하기 전에는 다른 화면으로 갈 수 없다.
  • 다른 탭 계정으로 로그인하면 올바른 탭을 안내한다.
  • 학생은 다른 학생의 할 일·제출물·점수를 볼 수 없다.
  • 학생은 수업현황 기록과 종합의견을 볼 수 없다.
  • 제출 기간 밖에는 제출 버튼이 막힌다. 지각 허용 과제는 감점을 미리 보이고, 채점표의 감점과 같다.
  • 한 과목의 이번 주 마감 할 일을 모두 체크하면 그 과목 몬스터가 생긴다.
  • AI로 보낸 글에 학생 이름이 들어 있지 않다.
  • 나이스 바이트 계산이 한글 3, 영문·숫자·공백 1, 줄바꿈 2 규칙과 맞는다.
  • 수업계가 교체를 승인하면 시간표와 해당 반 학생 화면에 바로 반영된다. 교체 사유는 학생에게 보이지 않는다.
  • 반려할 때 사유가 없으면 반려할 수 없다.
  • 내보내기·백업 파일에 비밀번호가 없다.
  • 기능 권한에서 끈 메뉴는 해당 역할 화면에 보이지 않는다.
  • 🔜 진급 처리 뒤에도 학생 아이디와 지난 기록이 그대로 이어진다. 졸업 학생은 로그인할 수 없다.
  • 🔜 담임이 확정한 출결은 확정 표시가 붙는다.
  • 확인 방법: 데모 데이터로 역할별 시나리오 점검 + 실제 학교 시범 운영.
