1. 추진 배경 및 문제 정의 (Background & Problem Statement)

1.1 교실 현장의 구조적 문제

학교 현장에서 담임 및 교과 교사는 수업 설계와 학생 생활지도라는 본질적 교육 활동 외에도 일상적인 학급 운영 기록과 공공 교육행정 시스템 처리에 막대한 시간을 소모하고 있다. 기존 업무 환경의 핵심 병목은 다음 네 가지 구조적 단절에서 비롯된다.

  1. 학급 일상 기록과 공공 행정 시스템(4세대 나이스·업무포털) 간의 이중 입력 단절

    • 교실 현장에서 수시로 발생하는 출결 변동, 교과 수행평가 성취도, 학생 상담·관찰 누가기록, 주간 학급시간표 변경 사항을 교사용 기록장에 먼저 정리한 뒤, 시·도교육청 업무포털에 공동인증서로 재로그인하여 4세대 나이스(NEIS)의 복잡한 다단계 메뉴를 찾아 다시 수작업으로 옮겨 적어야 한다.
    • 별도 설치형(데스크톱 창) 보조 도구를 사용할 경우, 교사가 기존 브라우저에 띄워 둔 업무포털 세션과 중복 로그인이 발생해 기존 작업 세션이 강제로 끊기거나 기관 보안 정책상 실행 파일 설치가 제한되는 문제가 발생한다.

  2. 학기 말 서술형 평가·학생부 기재 및 일상 행정 문서 작성의 과도한 시간 부담

    • 학기 말마다 학급 전 학생의 행동특성 및 종합의견(행발)과 전 과목 교과 평어(학기말종합의견)를 개별 특성과 성취수준에 맞춰 작성하고, 교육부 「학교생활기록부 기재요령」의 엄격한 금지어·어미·분량 규칙을 일일이 대조하는 데 수십 시간이 소요된다.
    • 현장체험학습·학사 안내 등을 위한 가정통신문과 행정업무 운영편람 서식(항목 기호 위계, 일시·금액 표기, 끝맺음 규격 등)을 갖춰야 하는 공문 기안문 작성 역시 반복적인 행정 피로를 유발한다.

  3. 반복적인 일상 복무 신청의 높은 절차적 마찰

    • 조퇴·외출·연가·특별휴가(육아시간, 가족돌봄 등) 등 54종에 달하는 근무상황 신청과 관내·관외·연수 출장, 시간외근무 신청을 처리할 때마다 업무포털 로그인 → 나이스 복무 메뉴 이동 → 기간·사유·종류별 필수 항목 입력 → 개인결재선 또는 결재자 지정 → 상신 절차를 매번 처음부터 반복해야 한다.

  4. 상용 생성형 AI 활용 시 개인정보 유출 위험 및 교육청 지침 위반 딜레마

    • 범용 생성형 AI에 학생 실명, 상담 내역, 성적, 건강·가정사 정보를 그대로 입력할 경우 「개인정보 보호법」 및 시·도교육청 「교사용 생성형 AI 활용 가이드라인」에 저촉되며 심각한 민감정보 유출 위험을 초래한다.
    • 또한 AI가 생성한 문장을 검증 없이 학교생활기록부에 그대로 기재하는 행위는 교육부 기재요령상 엄격히 금지되어 있으며, 유료 AI API를 중앙 서버에서 무제한 중계할 경우 과도한 운영 비용으로 인해 서비스의 장기적 지속가능성이 훼손된다.

1.2 제품 비전 및 해결 전략

본 프로젝트는 기존 학급 운영 플랫폼 클래너(Clanner)를 교실 수업 지원 · 학급 기록 관리 · AI 초안 보조 · 교육행정 시스템 자동 연동을 단일 신뢰 경계 안에서 완결하는 차세대 통합 워크스페이스로 고도화하는 것을 목표로 한다.

> 핵심 제품 철학: "기록은 교실의 흐름 속에서 한 번만, 초안과 행정 전달은 안전하고 정밀하게, 최종 판단과 승인은 언제나 교사가(Human-in-the-Loop)."

이를 실현하기 위해 다음 4대 핵심 축을 유기적으로 설계·구현한다.

  • [축 1] 개인정보 보호 내재화 이원화 AI 아키텍처 (Dual-Track AI): 교실 보조 모니터(학생 화면) 실시간 제어까지 확장된 대화형 업무 비서 **클래너 AI**와, 교사 개인 API 키(BYOK)로 서버를 거치지 않고 행발·교과 평어·가정통신문·공문 초안을 생성하고 기재요령을 자동 점검하는 작성 도우미 워크스페이스 구축.
  • [축 2] 브라우저 네이티브 통합 확장프로그램 (클래너 업무 지원): 별도 설치 파일 없이 기존 브라우저 세션 위에서 동작하는 시·도교육청 업무포털 자동 로그인, 근무상황(54종)·출장·시간외근무 복무 자동 상신, 그리고 출결·성취도·누가기록·주간 시간표·행발·교과 평어 등 나이스 6대 영역 정밀 자동입력 및 즉시 되돌리기(Undo) 구현.
  • [축 3] 신규 플랫폼 페이지 및 모던 2.0 사용자 경험: 신규 핵심 도구 페이지(/tools/writing), 실제 제품 경험을 즉시 체험하는 차세대 인터랙티브 랜딩 페이지(/new), 명도 대비와 시각적 위계를 정교화한 모던 2.0 테마 시스템 도입.
  • [축 4] 다계층 심층 방어 보안 설계 (Security & Privacy by Design): 영지식(Zero-Knowledge) 클라이언트 종단간 암호화(AES-256-GCM), AI 발신 전후 이중 비식별화 및 기기 전용(On-Device) 라우팅, 확장프로그램 제로 네트워크(connect-src 'none') 격리 및 ECDSA P-256 단기 서명 인가 체계 확립.

2. 목표 사용자 및 핵심 설계 원칙 (Target Users & Design Principles)

2.1 핵심 페르소나 및 일과·학기 활용 시나리오

구분주요 업무 상황기존 방식의 고충 (Pain Point)고도화 후 목표 경험 (To-Be)
아침 등교 전업무포털 접속 및 오늘 교실 화면 준비포털 접속 후 인증서 선택·암호 입력, 공지 팝업 닫기, 나이스·에듀파인 각각 실행, 교실 TV 안내문·시간표 수동 세팅확장 사이드바에서 PIN 6자리 해제 후 [둘 다 열기] 원클릭으로 포털 로그인 및 나이스·에듀파인 자동 진입, 클래너 AI로 오늘의 안내·타이머·시정표 즉시 반영
수업 및 일과 중출결·관찰·평가 기록 및 학생 참여 활동종이 수첩·엑셀에 임시 메모 후 방과 후에 다시 정리, 추첨·모둠 점수판에 학생 이름 노출 우려PIN 보호 기반 학급 기록 즉시 누적, 기기 전용 AI 명령으로 개인정보 외부 전송 없이 결석자 제외 발표자 추첨·자리배치·체크리스트 화면 송출
방과 후 행정조퇴·출장·시간외근무 신청 및 공문·안내문 기안복무 신청 창마다 날짜·시각·사유·결재선 반복 지정, 공문 항목 기호·날짜·금액 표기 수작업 대조전용 신청 창에서 프리셋 클릭 한 번으로 중복 검증 후 결재선 지정·자동 상신까지 완료, 작성 도우미로 가정통신문·공문 초안 생성 및 행정 서식 자동 검사 후 복사
주간·학기 말시간표 변동 반영, 행발·교과 평어 작성 및 나이스 이관20여 명 학생별 행발·과목별 평어 수백 건 작성 및 기재요령 금지어 육안 검수, 나이스 칸마다 복사·붙여넣기 반복 및 행 밀림 사고 위험공개 관찰기록·성취수준 연동 AI/문장 은행으로 초안 생성 및 규칙 자동 점검 → 확장프로그램이 학생 번호를 대조하여 나이스에 일괄 입력·독립 재조회 검증(오류 시 즉시 되돌리기)

2.2 5대 핵심 설계 원칙

  1. 영지식 암호화 및 최소 수집 원칙 (Zero-Knowledge & Data Minimization)
    • 학생 식별 정보와 민감 기록은 반드시 교사 기기에서 암호화된 상태로만 서버에 저장하며, 서비스 운영자나 중앙 서버조차 평문을 열람할 수 없도록 설계한다.
  2. 교사 주도권 보존 및 법령·지침 준수 (Human-in-the-Loop & Compliance)
    • AI는 '초안 보조'와 '구조화된 실행 계획 미리보기'까지만 수행하며, 학교생활기록부 문구 채택·나이스 반영·결재 상신의 최종 통제권은 항상 교사에게 둔다.
  3. 쓰기 후 독립 검증 및 안전 실패 (Verify-After-Write & Fail-Closed)
    • 공공 행정 화면 자동화는 단순 클릭 성공을 완료로 간주하지 않는다. 반드시 저장·상신 후 독립적인 재조회를 통해 화면 값이 입력 의도와 일치함을 검증하며, 알 수 없는 알림창·응답 지연·탭 숨김 감지 시 자동 재시도 없이 즉시 안전 중단하고 잠금 처리한다.
  4. 한 화면 한 과업의 저부하 UX (One-Screen, One-Task Experience)
    • 좁은 브라우저 사이드바와 복잡한 행정 폼에서 교사의 실수를 줄이기 위해 현재 단계에서 해야 할 행동 하나만 명확히 제시하고, 상세 진단 코드는 접힘 영역으로 분리한다.
  5. 무서버 과금 부담 및 운영 지속가능성 (Zero-Bottleneck Sustainability)
    • 대량 토큰이 소요되는 서술형 초안 작성은 교사 개인 무료 API 키 기반 브라우저 직접 통신(BYOK)과 정적 문장 은행을 결합하고, 나이스 공개 시간표는 브라우저 지연 동기화(Lazy Sync)로 처리하여 중앙 서버 비용과 부하를 최소화한다.

4. 상세 기능 요구사항 (Functional Requirements)

4.1 신규 페이지 추가: AI 교육 문서·학생부 초안 워크스페이스 (작성 도우미, /tools/writing)

교사가 가장 많은 서술 에너지를 쏟는 행동특성 및 종합의견(행발), 교과 평어, 가정통신문, 공문 기안문 4개 영역을 단일 워크스페이스로 통합한 신규 독립 페이지(/tools/writing)를 구축한다.

FR-WR-01. 교사 개인 키(BYOK) 원클릭 연결 및 무서버 직접 스트리밍 엔진

  • 요구사항 상세:
    • 무료 등급(BASIC)을 포함한 모든 교사가 비용 장벽 없이 사용할 수 있도록 개인 Google AI Studio 무료 API 키 1개를 연결하는 구조를 채택한다.
    • 한국어 서술 품질과 일일 무료 제공 한도(분당 30회, 일 14,400회)를 모두 충족하는 단일 검증 모델(gemma-4-31b-it)로 고정하여 교사의 모델 선택 혼란을 제거한다.
    • 직관적 3장면 모션 온보딩: 복잡한 스크린샷 대신 UI 변경에 영향받지 않는 단순화 모션 그래픽 3단계(① AI Studio 키 발급 화면 열기 → ② API 키 생성 위치 하이라이트 → ③ 붙여넣기 및 자동 검증)로 안내한다.
    • 입력창에 키(AIza… 등)를 붙여 넣는 즉시 형식 검사와 비과금 모델 목록 조회로 유효성을 자동 검증하고, 성공 시 학생 자료 암호화 키(dbKey)로 암호화하여 계정 설정(profiles.settings.writing_ai_key)에 암호문과 끝 4자리 식별값만 저장한다.
    • 직접 호출 및 탄력적 재시도: 모든 생성 요청은 클래너 서버를 거치지 않고 교사 브라우저에서 Google API로 직접 SSE(Server-Sent Events) 스트리밍 호출한다. 분당 입력 토큰 한도(16,000 TPM) 보호를 위해 요청 시작 간격 최소 2초·최대 3개 동시 요청으로 제어하며, 일시적 서버 혼잡(503) 시 30초·60초·90초 점진 대기로 최대 5회 자동 재시도하고 할당량 초과(429) 시 재사용 가능 시각을 명확히 안내한다.
  • 수용 기준 (Acceptance Criteria):
    • 키 연결 시 브라우저 비밀번호 자동 저장 팝업이 오작동하지 않아야 하며, 미연결 입력 상태에서 이탈 시 미저장 변경 보호 경고가 작동해야 한다.
    • 잘못된 키, 기관(학교) 워크스페이스 계정의 API 발급 제한, 네트워크 오류를 각각 구분된 한국어 해결 안내로 표시해야 한다.

FR-WR-02. 행동특성 및 종합의견(행발) 초안 작성 및 완곡화 교정

  • 요구사항 상세:
    • 학생별 특성 입력 및 관찰기록 연동: 재적 명부 학생별로 자유 서술·키워드 입력칸(최대 600자)과 4대 영역(학습·교우·생활·특기) 빠른 키워드 칩을 제공한다. [관찰기록 불러오기] 실행 시 당해 학년도 누가기록 중 공개 관찰기록만 선별하여 불러오며, 상담 기록·비공개 기록·가정환경(family) 유형 기록은 원천 배제한다.
    • 배치 생성 및 이어서 하기: 5명 단위로 묶어 프롬프트를 구성하되, 이미 초안이 있는 학생은 건너뛰고 특성이 입력된 미생성 학생만 선택 생성(이어서 하기)한다. 완료된 학생의 초안은 즉시 학생 단위로 암호화하여 전용 테이블(writing_drafts)에 자동 저장한다.
    • 행발 전용 문체 원칙 및 부족한 점 경중 제어:
      • 300400자(56문장) 분량, 명사형 어미 종결, 역접 접속사(그러나 등)·서열 비교(누구보다 등)·과도한 강조 부사 배제 원칙을 적용한다.
      • 행동 개선이 필요한 특성은 반대로 뒤집어 허위 장점으로 기재하지 않고 경중에 따라 차등 처리한다: ① 가벼운 특성(목소리 작음, 장난 등)은 생략하거나 긍정적 잠재력으로 전환, ② 보통·심한 특성은 단 한 문장으로 완곡하게 서술하되 개선 변화(점차 나아짐) 또는 성장 기대(~할 것으로 기대됨)로 마무리하며, 건강·가정사·진단명은 입력되더라도 초안 본문에 반영하지 않는다.
    • 부족한 점 분리 제어 및 교사 문체 맞춤: 응답 구조에서 부족한 점에 해당하는 문장(concern)을 별도로 식별하여 결과 카드에 시각적으로 표시하고, 교사가 원클릭으로 [빼기](즉시 문장 제거) 또는 [더 부드럽게](해당 문장만 재완곡화)를 선택할 수 있게 한다. 또한 교사가 본인의 기존 행발 예시 3~5건을 등록하면 별도 모델 재학습 없이 요청 시 문체 예시(Few-shot)로 함께 반영하는 선택 기능을 지원한다.
  • 수용 기준 (Acceptance Criteria):
    • 일부 묶음 요청이 네트워크나 서버 혼잡으로 실패하더라도 성공한 학생의 초안은 유실 없이 암호화 저장되어야 하며, 재실행 시 실패한 학생만 이어서 생성되어야 한다.

FR-WR-03. 교과 평어 초안 작성 및 2022 개정 교육과정 성취기준 문장 은행

  • 요구사항 상세:
    • 평가 데이터 자동 연동: 학기와 과목을 선택하면 클래너 평가기록에 등록된 성취기준 코드와 학생별 성취수준(◎ 잘함 · ○ 보통 · △ 노력 요함)을 자동으로 불러온다.
    • 하이브리드 문장 마련 방식:
      1. 정적 문장 은행 (기본, API 키 불필요): 2022 개정 초등 교육과정 전 학년군·과목 성취기준 원문과 국가교육과정정보센터(NCIC) 성취수준을 기반으로 사전 구축·검증된 수준별 평가 문장 풀을 학년군·과목 단위 정적 자산으로 지연 로드한다. 허위 기재 방지 장치로서, 구체적 수업 활동 장면이 포함된 문장은 교사가 실제 우리 반에서 실시한 활동만 검색·체크하여 선택하게 하고, 선택한 문장 풀 안에서만 학급 학생들에게 겹치지 않도록 순환 배정한다.
      2. AI 맞춤형 평어 생성: 교사가 우리 반 수행평가 과제 설명을 입력하면 해당 활동 맥락에 꼭 맞는 성취수준별 평가 문장을 실시간 생성한다.
    • 엄격한 평가형 문체 엔진:
      • 교과 평어는 생활 태도나 성장 서사가 아닌 성취 도달도 평가 문장이어야 한다. 주어 생략, 현재형 명사형 평가 어미(~익힘, ~찾아냄, ~설명함, ~판단함, ~서술함 등)로 통일하며, 과거형(~하였음), 비평가성 태도 어미(~참여함, ~노력함, ~시도함), 진행형 어미(~해 봄, ~배워 감, ~고 있음), 모호한 표현(무난함)을 전 수준에서 배제한다.
      • 노력 요함(△) 수준 역시 막연한 격려나 기대가 아니라 수준 한정 수식(기초적인 수준에서 ~을 찾아냄, 도움 자료를 활용하여 ~함, ~을 구분하는 데 어려움을 겪음 등)을 다변화하여 특정 문장 틀에 편중되지 않게 조립한다.
    • 학생별 조립 및 중복 검사: 학생의 성취기준별 도달 수준 문장을 과목 단위로 결합한 뒤, 한 학생의 글 안에서 동일한 종결어나 수식어가 연속 반복되는지 자동으로 검사·표시한다.
  • 수용 기준 (Acceptance Criteria):
    • API 키를 연결하지 않은 교사도 문장 은행을 통해 전 과정 평어 조립·편집·저장이 가능해야 하며, 교사가 선택하지 않은 활동 장면 문장이 학생에게 자동 배정되어서는 안 된다.

FR-WR-04. 가정통신문 · 공문 기안문 초안 작성 및 행정 서식 자동 검사기

  • 요구사항 상세:
    • 핵심 사실 기반 생성: 제목, 일시(새 항목 초기화 시 폼을 연 순간의 기기 현재 시각 HH:mm 기본 적용), 장소, 대상, 소요 비용, 협조 사항, 붙임 문서 등 사실 정보만 입력하면 학부모 안내용 가정통신문 또는 기관 내부 결재·시행용 공문 기안문 초안을 생성한다.
    • 행정업무 운영편람 기반 공문 서식 자동 검사기 (API 키 불필요):
      • 항목 기호의 계층 순서(1. → 가. → 1) → 가)) 및 단계별 들여쓰기(2타 기준) 정합성 검사.
      • 표준 날짜 표기(YYYY. M. D.(요일)) 및 24시간제 시각(HH:mm) 형식 검사.
      • 금액 표기 시 아라비아 숫자와 한글 병기(예: 금150,000원(금일십오만원)) 여부 점검.
      • 본문 하단 붙임 표시 형식 및 마지막 줄 본문 끝 두 칸 띄어쓰기 후 ' 끝.' 마감 규격 검증.
    • K-에듀파인 연계 복사: 별도 클라이언트 프로그램으로 동작하는 K-에듀파인 문서 기안기에 즉시 붙여 넣을 수 있도록 [제목 복사] · [본문 복사] 원클릭 버튼과 안내를 제공한다.
  • 수용 기준 (Acceptance Criteria):
    • AI 생성 본문뿐 아니라 교사가 직접 붙여 넣거나 수정한 공문 텍스트에 대해서도 실시간으로 서식 위반 항목과 교정 가이드를 정확히 표시해야 한다.

FR-WR-05. 학교생활기록부 기재요령 실시간 규칙 검사기 및 문맥 바로가기

  • 요구사항 상세:
    • 2026학년도 교육부 학교생활기록부 기재요령 및 교육청 지침을 코드화한 공통 규칙 엔진(recordRules)을 결과 카드에 실시간 적용한다.
    • 검사 범위: 교내·외 대회 및 수상 실적, 공인어학성적·자격증, 해외 활동, 사교육·대학·기관·상호·강사명, 부모의 사회·경제적 지위 암시 어휘, 방과후학교(교과 영역 금지), 허용 목록 외 영문 표기, 특수기호·번호 나열, 명사형 어미 미종결, 마침표 누락, 동일 어미 연속, 마스킹 토큰 잔존 여부, 적정 글자 수 및 학급 전체 학생 간 3어절 이상 동일 표현 중복(3명 이상 사용 시 경고).
    • 비차단 보조 원칙: 학생부 기재의 최종 권한과 책임은 교사에게 있으므로 규칙 경고는 저장을 강제로 막지 않고 시각적 점검 배지로 안내하되, 나이스 시스템이 물리적으로 거부하는 입력 바이트 상한 초과(행발 15,000B, 평어 4,000B, 줄바꿈 제한 등)만 전송 직전에 사전 차단한다.
    • 문맥 유지 진입점: 기존 누가기록 학생 상세 화면에 [행발 초안] 버튼을, 평가기록 화면에 [교과 평어 초안] 버튼을 두어 선택된 학생이나 학기·과목 상태를 그대로 이어받아 작성 도우미 해당 탭으로 진입한다.

4.2 대화형 학급·교실 운영 비서 확대 고도화 (클래너 AI)

기존 학급 업무(일정, 할 일, 메모, 알림장, 시간표 등) 보조에 머물던 대화형 AI를 교실 현장의 실시간 학생 화면(/student-display) 설정 및 라이브 조작까지 포괄하는 통합 교실 운영 에이전트로 확대한다.

FR-AI-01. 다중 업무 구조화 계획(Plan) · 완결성 점검 · 실행 취소(Undo)

  • 요구사항 상세:
    • 자연어 요청을 분석하여 고정된 도메인 도구 스키마 기반의 변경 계획(Plan)을 생성하고, 교사가 미리보기 카드에서 변경 전후 내역을 확인·승인한 뒤에만 실제 서비스·리포지토리·조건부 RPC로 반영한다(임의 SQL 생성·실행 원천 불가).
    • 복합 명령 누락 방지 루프: 교사가 한 문장에 두 가지 이상의 변경(예: "할 일 태그 만들고 내일 일정 추가해 줘", "QR 띄우고 5분 타이머 켜 줘")을 함께 요청했을 때 모델이 일부 도구만 호출하고 종료하는 현상을 막기 위해, 복합 요청 패턴 감지 시 동일 스트림 내에서 미처리 변경 여부를 자동 재점검하여 단일 계획으로 병합한다.
    • 동시성 보호 및 역순 실행 취소: 계정 설정 및 워크스페이스 데이터 저장 시 기대 판본(CAS / Revision)을 대조하여 타 탭·기기 변경과의 덮어쓰기 충돌(409)을 막고, 실행 저널을 기록하여 적용 직후 원클릭 [실행 취소]로 이전 상태를 복원한다. 고정 메모(note_date NULL)의 제목 지정·이름 변경·기간 메모와의 분리 조회도 완벽히 지원한다.

FR-AI-02. 교실 학생 화면(/student-display) 통합 설정 및 라이브 제어

  • 요구사항 상세:
    • 화면 설정 및 위젯 레이아웃 자동화: 자연어 지시만으로 학급 D-day, 날짜별 오늘의 안내, 숙제·준비물, 오늘의 질문 및 자동 전환 목록, 하교 전 확인 체크항목, 예약 안내 방송(기기 내 로컬 한국어 음성 합성)·반복 종소리, 시정표, 기본 교시 시각, 타이머 프리셋을 일괄 구성한다. 숨겨져 있던 대상 위젯은 저장 시 자동으로 활성화하고 그리드 내 빈 공간으로 겹침 없이 배치하며, 위젯 크기·이름 변경도 함께 처리한다.
    • 실시간 화면 조작 (Live Control): 보조 모니터나 교실 TV에 띄우는 학생 창이 닫혀 있으면 클릭 시점에 사용자 제스처를 보존하여 새 창을 자동으로 열고 연결을 확인한 뒤, QR 코드 즉시 표시(링크 별칭 동시 저장 및 이름만 단독 변경 포함), 타이머 시작·일시정지·초기화, 스톱워치 제어, 동전 던지기·주사위 굴리기 연출을 즉시 전달한다.
    • 수동 편집 충돌 보호 (displayDraftRegistry): 교사가 학생 화면 제어판이나 학생 창에서 판서 필기, QR 편집, 시정표 편집, 위젯 레이아웃 편집을 수동으로 진행 중인 경우 이를 메모리 레지스트리로 즉시 감지하여 AI 적용이 작업 중인 내용을 덮어쓰지 않도록 사전 안내 후 대기한다.

FR-AI-03. 기기 전용(On-Device) 학생 참여 화면 표시 및 지목 추첨

  • 요구사항 상세:
    • 교실 화면에 학생 추첨, 명렬표 체크판, 자리배치도, 체크리스트 완료 인원 현황을 띄우는 기능은 학생 개인정보가 외부 모델 문맥으로 넘어가지 않도록 기기 전용 실행 경로로 분리한다.
    • 특히 자연어 추첨("오늘 결석한 학생 빼고 지난번 당첨 안 된 남학생 2명 뽑아 줘", "○○이 빼고 추첨해 줘") 요청 시, 지목된 학생 호칭만 세션 난수 토큰([학생N])으로 치환해 조건만 해석하고 실제 후보 풀 계산·난수 추첨·당첨자 표시는 전량 교사 기기 내부에서만 수행한다. 당첨 학생 실명이나 번호는 AI 대화 이력이나 서버 전송 본문에 절대 남기지 않는다.

4.3 통합 브라우저 확장프로그램 개발 (클래너 업무 지원)

기존 단순 입력 도우미를 전면 개편하여, 별도 PC 설치 프로그램 없이 Chrome·Edge·Whale·Aside 등 모든 Chromium 계열 브라우저에서 단일 패키지로 동작하는 통합 행정 자동화 확장프로그램 **클래너 업무 지원**을 구축한다.

FR-EX-01. 크로스 브라우저 단일 사이드바 아키텍처 및 단계형 UI

  • 요구사항 상세:
    • 런타임 브라우저 환경 감지(browser-target)를 통해 단일 빌드 패키지로 Chrome·Edge 사이드 패널과 네이버 Whale 네이티브 사이드바(새 탭 전환 시 사이드바 유지 처리 포함), 그리고 클래너 PWA 앱 창 실행 시 우측 도킹 팝업 창 모드를 모두 지원한다.
    • 기존 나이스 입력 DOM과 신규 React 기반 패널 UI는 ShadowRoot로 스타일과 스코프를 완전 격리한다.
    • 하단 내비게이션은 홈 · 복무 · 나이스 입력 · 설정으로 구성하고, 상단 우측에는 현재 보안 상태를 한눈에 보여 주는 잠금 상태 칩과 설정 바로가기를 배치한다. 잠금 상태에서는 어떤 탭으로 진입하든 6자리 자동 로그인 PIN 해제 화면을 최우선 게이트로 표시한다.

FR-EX-02. 시·도교육청 업무포털 자동 로그인 및 나이스 · K-에듀파인 원클릭 진입

  • 요구사항 상세:
    • 단계별 초기 온보딩: 시·도교육청 선택 → 해당 포털·나이스·K-에듀파인 사이트 연결 권한 허용 → 기존 공동인증서 암호 입력(또는 '저장하지 않고 쓰기' 선택) → 신규 6자리 자동 로그인 PIN 생성 및 재확인을 한 화면에 한 단계씩 안내하여 인증서 암호와 PIN의 혼동을 원천 방지한다.
    • 지능형 공동인증서 로그인: 포털 접속 시 이미 로그인된 세션이면 암호 입력 없이 즉시 통과한다. 로그인이 필요한 경우 기억된 인증서(사용자·만료일·발급자 일치 검증, 만료 시 유효 갱신 인증서 재선택 안내)를 자동 선택하고 암호를 단 1회만 입력·제출한다(실패 시 계정 잠금 방지를 위해 재시도 없이 즉시 중단 및 자동 로그인 잠금).
    • 포털 예외 창 복구 및 원클릭 시스템 실행: 로그인 전 인증서 보안 모듈 세션 만료 팝업(SweetAlert2 등) 감지 시 자동으로 닫거나 초기 로그인 주소로 안전 갱신하며, 로그인 후 메인 화면의 공지 슬라이드 팝업은 쿠키 변조 없이 닫기 버튼을 처리한다. 포털 호스트의 팝업 차단을 선택 권한(contentSettings)으로 허용한 뒤 **[나이스 열기] · [K-에듀파인 열기] · [나이스와 K-에듀파인 함께 열기]**를 수행하며, 열린 K-에듀파인 탭은 교육청별 공식 호스트 주소로 긍정 확인한다.

FR-EX-04. 독립 재조회 완료 판정 및 '방금 입력 되돌리기(Undo)'

  • 요구사항 상세:
    • 자동입력 엔진은 각 항목을 쓰기 직전 해당 셀·상세창의 기존 나이스 값을 사이드 패널 메모리에만 스냅샷으로 보관한다(동일 값은 쓰지 않고 자동 건너뛰기).

      • 기존 값을 수정했던 출결·성취도·누가기록·행발·평어는 원래 값으로 재저장 후 재조회 확인(입력 전이 빈칸이던 출결은 상세창 초기화 후 빈칸 확인).
      • 원래 빈칸에 새로 추가했던 성취도·누가기록·교과 평어는 다른 체크 행이 없음을 전수 확인한 뒤 해당 줄만 선택하여 나이스 [삭제] 절차와 확인 알림 검증 후 재조회로 삭제 완료를 확정한다.
      • 복원이 불가능하거나 입력 이후 교사가 나이스에서 직접 수정한 항목은 임의로 건드리지 않고 '직접 확인' 목록으로 투명하게 분류한다.

4.4 복무 자동 상신 워크플로우 (근무상황 54종 · 출장 · 시간외근무)

클래너 업무 지원 확장프로그램 내 복무 탭과 전용 와이드 신청 창을 통해 교사의 일상 복무 신청부터 결재 상신까지 전 과정을 자동화한다.

sequenceDiagram
    actor T as 교사
    participant W as 전용 와이드 복무 신청 창
    participant S as 확장 사이드바 조정기
    participant N as 4세대 나이스 (복무 · 기안창)

    T->>W: 프리셋 선택 또는 날짜·시각·종류·사유 입력 (필요 시 프리셋 동시 등록)
    W->>S: 실행 초안 전달 (BroadcastChannel, 창 자동 닫힘)
    S->>N: 업무포털 로그인 확인 및 대상 복무 화면 자동 이동
    S->>N: 신청 기간 기존 목록 조회 (동일 종류 중복 · 타 복무 시간 겹침 검사)
    alt 중복 또는 시간 겹침 발견
        S-->>T: 신청 창 열기 전 즉시 안전 중단 및 겹친 기존 내역 안내
    else 중복 없음 확인
        S->>N: [신청] 창 열기 및 종류·기간·시각·필수 추가칸 입력 (다건 시 행추가 반복)
        S->>N: 나이스 화면에 반영된 전체 칸 · 자동 계산 시간 합계 재판독 대조
        alt 실행 범위 = ① 채우기까지 (또는 계정별 직접 선택 항목 포함)
            S-->>T: 대조표 표시 및 교사 직접 [승인요청] 안내
        else 실행 범위 = ② 결재선까지 / ③ 자동 상신
            S->>N: [승인요청] 1회 클릭 (임시저장 생성 및 기안문서상신 창 진입)
            S->>N: 기안 기간 재대조 후 결재선 지정 (개인결재선 또는 결재자 직접 지정) 및 결재선 표 대조
            alt 실행 범위 = ② 결재선까지
                S-->>T: 임시저장 안내 및 교사 직접 [상신] 안내
            else 실행 범위 = ③ 자동 상신 (선행 성공 + 종목별 명시 동의 완료 시)
                S->>N: [상신] 1회 클릭 → 확인 알림 검증 → 목록 재조회 '상신(진행)' 확인
                S-->>T: 최종 상신 완료 결과 표시 (미확인 시 중복 방지 잠금 활성화)
            end
        end
    end

5.1 제1계층: 영지식 기반 학생 개인정보 종단간 암호화 (Client-Side E2EE)

  1. 필드 컨텍스트 결속 암호화 (AES-256-GCM + AAD)
    • 학생 성명, 번호, 성별, 연락처, 출결 사유, 평가 점수·코멘트, 상담·관찰 기록, 체크리스트, 작성 도우미 초안(writing_drafts), 교사 개인 Google AI 키(writing_ai_key), 점수판 연동 명부는 모두 교사 브라우저에서 AES-256-GCM(매 암호화마다 새로운 12바이트 암호학적 난수 IV 생성)으로 암호화한 뒤 서버로 전송한다.
    • 각 암호문에는 테이블·컬럼 식별자를 **추가 인증 데이터(AAD, fieldEncryptionContext)**로 결속하여, 공격자가 DB 내 다른 컬럼으로 암호문을 이식하여 복호화를 유도하는 교차 컬럼 치환 공격(Ciphertext Transplanting)을 원천 차단한다.
  2. 비추출 기기 키 래핑 및 엄격한 PIN 생명주기 관리
    • 교사의 6자리 학생 정보 보호 PIN으로부터 PBKDF2-SHA256으로 유도된 키를 사용해 데이터 암호화 키(dbKey)를 감싸며, 브라우저 내에서는 IndexedDB의 비추출성(extractable: false) WebCrypto 키와 자격정보 SHA-256 지문을 결합해 안전하게 유지한다. 반복·연속 숫자(000000, 123456 등)는 취약 PIN으로 생성 단계에서 차단한다.
    • PIN 미해제 또는 세션 만료·계정 전환 시 대시보드 학생 위젯, 모달 포털, 통합검색 인덱스, 브라우저 로컬 스토리지 어디에도 학생 실명이나 평문 기록을 마운트·잔존시키지 않는다.
    • PIN 분실 시 복구 백도어를 두지 않는 영지식 원칙을 지키며, 교사가 명시적 확인 문구(초기화하겠습니다)를 직접 입력한 경우에만 단일 트랜잭션 RPC(reset_my_student_data_for_pin)와 외래키 ON DELETE CASCADE로 기존 암호화 학생 자료 전체를 원자적으로 파기한다.

5.2 제2계층: AI 개인정보 이중 차단 게이트 및 비식별화 설계

  1. 전송 정보 최소화 및 기기 전용(On-Device) 로컬 라우팅
    • 명렬표·자리배치·체크리스트 학생별 상태 조회, 시험 성적 평균·순위 질의, 학부모 면담·상담·건강(질병·투약·진단)·가정사 관련 표현이 포함된 요청은 외부 LLM 호출 전에 클라이언트 경계(privateStudentInput · outboundPrivacy)에서 즉시 감지하여 기기 전용 로컬 처리 경로로 분기하거나 외부 전송을 차단한다.
    • Google 캘린더·할 일 연동으로 가져온 일정 역시 Google API 제한적 사용 정책에 따라 외부 AI 모델 입력에서 자동 배제하고 AI를 통한 변조를 막는다.
  2. 세션 난수 시드 기반 정밀 마스킹 (createOutboundMask & redaction)
    • 외부 AI 호출이 허용된 작업에서도 명부상 학생 이름과 호칭(성을 뺀 이름 및 남궁·선우·독고 등 한국어 복성 16종 파생 호칭 포함)을 기기 메모리에만 존재하는 대화별 난수 시드로 섞어 [학생N] 토큰으로 치환한다(명부 순번·이름 길이 추론 방지).
    • 내국인 주민등록번호(1~4)뿐 아니라 외국인등록번호·거소신고번호(5~8), 휴대전화·일반전화(하이픈·점·공백 구분 변형 포함), 이메일, 계좌번호, 외부 URL([링크N])을 고신뢰 정규식으로 탐지한다.
    • 긴 메모나 알림장을 분할해 읽거나 길이를 자를 때에도 이름·연락처·URL 한가운데가 잘려 마스킹을 우회하는 반토막 노출이 발생하지 않도록 어절·패턴 안전 경계 분할(chunkSafeReadLines, cutOutsideLinks)을 강제한다.
  3. 서버 2차 재검증 및 BYOK 무서버 격리
    • 대화형 클래너 AI 서버 라우트는 모델 호출 및 쿼터 차감 직전에 요청 본문 전체를 동일 패턴으로 재검사(sensitiveLabelsInBody)하여 미가림 민감 패턴이 단 하나라도 발견되면 로그에 원문을 남기지 않고 즉시 400으로 거부한다.
    • 작성 도우미는 클래너 서버를 전혀 거치지 않는 교사 브라우저 → Google API 직접 통신 구조를 취해 중앙 서버 내 프롬프트·초안 평문 통과 가능성을 0으로 만들며, 발신 직전 클라이언트 최종 관문에서 연락처·고유식별번호 포함 시 전송을 원천 차단하고 건강·가정사 어휘 포함 시 교사의 명시적 재확인 없이는 발신하지 않는다.

5.3 제3계층: 확장프로그램 제로 네트워크 격리 및 암호화 서명 인가

  1. 완전한 오프라인 실행 환경 (connect-src 'none') 및 최소 권한(optional_host_permissions)
    • 클래너 업무 지원 확장프로그램은 자체 네트워크 연결을 전면 차단(CSP: default-src 'self'; connect-src 'none')하여, 확장 내부에 전달된 학생 기록이나 공동인증서 암호가 외부 서버로 전송되는 경로가 기술적으로 존재하지 않음을 보장한다.
    • debugger, tabs, 쿠키, 클립보드 상시 읽기 권한을 요구하지 않으며, 원격 코드 다운로드·eval·MAIN world 스크립트 주입을 일절 사용하지 않고 빌드 시 해시가 검증된 정적 함수만 최상위 프레임(frameId === 0)의 격리 환경(ISOLATED world)에서 실행한다.
    • 사이트 접근 권한 역시 설치 시점에 일괄 요구하지 않고, 교사가 선택한 교육청 업무포털·나이스·K-에듀파인(탭 주소 확인 전용, 내부 화면 비접근) 호스트만 연결 클릭 시점에 선택적으로 요청한다.
  2. 원문 무전송 단기 암호화 인가 티켓 (ECDSA P-256 Grant)
    • 나이스 자동입력의 이용 권한(PRO 이상) 검증 시, 클래너 웹은 학생 데이터 본문을 서버로 보내지 않고 확장프로그램이 생성한 일회용 nonce와 전송 꾸러미의 SHA-256 해시값만 인가 함수(neis-authorize)로 보낸다.
    • 서버는 인증 및 등급 확인 후 해당 nonce·해시에 결속된 2분 만료 ECDSA P-256 전자서명 티켓만 발급하며(인가 이력 DB 미저장), 확장프로그램은 내장된 공개키(publicJwk, 빌드 시 개인키 포함 여부 강제 차단)로 서명과 해시 일치를 오프라인 검증한 뒤에만 입력을 개시한다.
  3. 전송 자료 메모리 휘발 및 확장 독립 암호화 금고 (ExtensionVault)
    • 클래너 웹에서 허용된 출처(externally_connectable) 포트를 통해 확장으로 전달된 자동입력 꾸러미는 디스크 저장소(chrome.storage)에 절대 기록하지 않고 열린 사이드 패널 메모리에만 최대 30분간 유지한 뒤 작업 확인·창 종료·새로고침·만료 시 즉시 파기한다.
    • 업무포털 자동 로그인용 공동인증서 암호는 클래너 웹 계정·PIN과 완전히 분리된 확장 전용 6자리 자동 로그인 PIN + 무작위 16바이트 Salt 기반 PBKDF2-SHA256(600,000회 이상) + 항목별 AES-256-GCM으로 암호화하여 로컬 전용 영역(chrome.storage.local)에만 보관한다(기기 간 클라우드 동기화 storage.sync 미사용, 오입력 시도 횟수 제한 및 지연 잠금, 일정 시간 경과·자리 비움 시 세션 마스터키 자동 소거).

5.4 제4계층: 데이터베이스(RLS) · 인프라 통제 및 법령·정책 투명성

  1. 데이터베이스 행 수준 보안(RLS) 및 서버 경계 방어
    • 모든 사용자 테이블에 PostgreSQL RLS(Row-Level Security)를 강제하고, 자식 테이블 쓰기 시 부모 외래키(학생·평가·반복업무·카테고리 등)의 본인 소유권까지 WITH CHECK로 교차 검증하여 계정 간 데이터 오염(IDOR 및 교차 Write DoS)을 차단한다.
    • 모든 SECURITY DEFINER RPC는 search_path를 고정하고 비로그인(anon·PUBLIC) 실행 권한을 회수하며, 유료 등급 한도와 관리자 기능은 클라이언트가 아닌 서버·DB 트랜잭션 잠금(pg_advisory_xact_lock) 및 서명 쿠키로 강제한다.
    • Google OAuth 단일 인증 체계(임의 이메일 가입 비활성화 및 허용 콜백 URL 화이트리스트 고정), 상태 변경 API의 무조건적 동일 출처(Origin) 검증, 리치 텍스트 DOMPurify 스킴·스타일 화이트리스트 정화, 웹 푸시 엔드포인트 도메인 화이트리스트 검증(SSRF 방어), CSV 내보내기 시 선두 수식 문자(=, +, -, @) 무력화, 에러 정규화(normalizeError)를 통한 스택·토큰·원문 로그 무노출을 전 구간에 적용한다.
  2. 법령 · 교육부 지침 준수 및 투명한 동의 거버넌스
    • 이용약관에 주민등록번호·외국인등록번호·여권번호 등 법령상 처리가 금지된 고유식별정보 입력 금지를 명시하고, 불필요한 이용 시간 세션 핑 수집을 폐지하여 최소 수집 원칙을 실천한다.
    • 기본 서비스 가입 동의와 클래너 AI 선택 동의, 작성 도우미(교사 개인 Google 키 직접 전송) 선택 동의를 각각 독립된 버전으로 분리 운영한다. 개인정보처리방침에는 외부 전송 항목, 국외 이전 수탁자, 확장프로그램의 브라우저 로컬 한정 보관 원칙을 기존 조항 체계를 보존한 하위 절(4-1, 4-2, 7-1, 7-2 등)로 정밀하게 고지한다.
