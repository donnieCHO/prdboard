PRD: 영광 마을배움 온라인 교재 사이트

문서 버전: v0.1 (초안) · 작성일: 2026-11-25 문서 성격: 사이트 제작 전 사전과제 문서. 개발자 또는 AI 코딩 도구에 이 문서를 그대로 넘겨 제작을 시작할 수 있게 작성함. 표시 규칙: [확정 필요]는 교사(기획자)가 정해야 하는 항목, (예시)는 실제 교재 내용으로 바꿔야 하는 항목.

1. 개요

1.1 한 줄 정의

영광 마을배움지원교재의 주제별 읽기 자료 → 퀴즈 → 관련 게임을 한곳에 모은, 초3~중3 학생용 온라인 교재 사이트.

1.2 배경

  • 영광 마을배움지원교재는 초등학교 3학년부터 중학교 3학년까지 쓸 수 있도록 수준별 자료로 구성되어 있다.
  • 종이 교재만으로는 학생 스스로 이해도를 확인하기 어렵고, 관련 앱·게임이 여기저기 흩어져 있어 수업 중 찾아 들어가기 번거롭다.
  • 주소 하나로 들어와서 "읽고 → 풀고 → 놀며 익히는" 흐름을 한 사이트에서 끝내고자 한다.

1.3 목표

구분목표
학생자기 수준에 맞는 읽기 자료를 읽고, 퀴즈로 바로 이해도를 확인하고, 게임으로 복습한다.
교사수업 시간에 주소(또는 QR) 하나만 안내하면 된다. 내용 수정은 코딩 없이 파일 하나만 고치면 된다.
운영로그인·서버 없이 무료로 운영할 수 있다. 학생 개인정보를 수집하지 않는다.

1.4 하지 않는 것 (범위 밖, 1차 버전 기준)

  • 회원가입·로그인, 학생별 성적 저장/교사용 성적 대시보드
  • 게임 자체 개발 (1차에서는 기존 앱·게임을 모아 연결만 한다)
  • 게시판, 댓글 등 학생 간 소통 기능

2. 사용자

사용자특징핵심 요구
초3~4 학생읽기 능력 차이 큼, 긴 글 부담, 터치 조작 익숙큰 글씨, 짧은 문단, 그림, 쉬운 단어
초5~6 학생스스로 탐색 가능퀴즈 즉시 채점과 해설, 게임 바로가기
중1~3 학생깊이 있는 내용 원함, 유치한 디자인 거부감심화 자료, 서술형/생각 질문
교사수업 준비 시간 부족, 기기 환경 다양수준·주제별 빠른 이동, 쉬운 내용 수정, 대화면(TV/전자칠판) 띄우기

사용 기기: 학교 태블릿(크롬북·갤럭시탭·아이패드), 교실 PC + 전자칠판, 학생 개인 스마트폰. → 모바일 우선 반응형 필수.

3. 콘텐츠 구조

3.1 수준(레벨) 체계 [확정 필요]

교재의 실제 수준 구분 방식에 맞춘다. 기본안은 3단계:

레벨대상표시 이름(예시)읽기 자료 기준
1초3~4🌱 새싹300~500자, 짧은 문장, 그림 위주
2초5~6🌿 줄기600~1,000자, 핵심 개념어 포함
3중1~3🌳 나무1,000~1,800자, 자료 해석·비교 포함

학년 대신 레벨 이름을 쓰면, 수준 차이가 있는 학생이 다른 레벨을 골라도 부담이 적다. 학년 표시는 보조 정보로만 둔다.

3.2 주제(단원) 구성 (예시) — 실제 교재 목차로 교체

#주제하위 내용(예시)
1영광의 자연과 지리바다·갯벌, 산, 섬(안마도·송이도 등)
2영광의 역사백제 불교 최초 도래지(법성포), 역사 인물
3영광의 산업굴비, 천일염, 모싯잎송편, 에너지
4영광의 문화와 축제법성포 단오제, 지역 축제
5우리 마을 탐구읍·면별 마을 이야기

3.3 콘텐츠 단위 (주제 × 레벨 = 1개 학습 세트)

한 학습 세트는 다음으로 구성된다.

  1. 읽기 자료 – 제목, 본문(문단), 이미지(+출처), 핵심 낱말 풀이
  2. 퀴즈 – 5~10문항
  3. 관련 게임 – 0~여러 개 (게임 모음 페이지와 공유)
  4. (선택) 생각해 보기 – 정답 없는 열린 질문 1~2개 (화면 표시만, 저장 안 함)

3.4 퀴즈 문항 유형

유형1차 지원비고
4지선다(객관식)✅기본 유형
O/X✅초3~4 권장
단답형(빈칸)✅정답 여러 개 허용(예: "굴비", "조기")
순서 맞추기 / 짝짓기⏳ 2차
서술형❌채점 불가 → "생각해 보기"로 대체

모든 문항은 정답 해설과 읽기 자료의 근거 문단 위치를 가진다 ("본문 2문단을 다시 읽어 보세요").

4. 기능 요구사항

우선순위: P0 = 1차 출시 필수, P1 = 있으면 좋음(1차 가능 시), P2 = 2차 이후

4.1 홈

  • [P0] 사이트 소개 한 줄, 레벨 선택(3개 큰 버튼), 주제 목록(카드형, 대표 이미지)
  • [P0] "게임 모음" 바로가기
  • [P1] 선택한 레벨을 기억(브라우저 저장)하여 다음 방문 시 유지
  • [P1] 교사용 안내 페이지 링크 (사용법, QR 코드)

4.2 주제 페이지 (학습 세트)

  • [P0] 상단 레벨 탭으로 같은 주제의 다른 레벨로 즉시 전환
  • [P0] 흐름 표시: ① 읽기 → ② 퀴즈 → ③ 게임
  • [P0] 읽기 자료: 이미지·캡션·출처, 핵심 낱말 강조(누르면 뜻 표시)
  • [P1] 글자 크기 조절(작게/보통/크게)
  • [P1] 읽어주기(TTS, 브라우저 내장 음성) – 초3~4 및 읽기 지원 필요 학생용
  • [P2] 오디오/영상 자료 삽입

4.3 퀴즈

  • [P0] 한 문항씩 풀기, 선택 즉시 정답/오답 표시 + 해설
  • [P0] 오답일 때 근거 문단으로 돌아가는 링크
  • [P0] 결과 화면: 점수, 틀린 문항 다시 보기, "다시 풀기", "게임하러 가기"
  • [P1] 보기 순서 섞기
  • [P1] 완료한 주제에 ✔ 표시(브라우저 저장, 개인정보 없음)
  • [P2] 결과 화면 캡처/인쇄용 "확인증" (학생이 이름을 직접 입력, 저장하지 않음)

4.4 게임 모음

  • [P0] 전체 게임 목록 페이지: 카드(썸네일, 게임 이름, 관련 주제, 권장 레벨, 플랫폼)
  • [P0] 필터: 주제별 / 레벨별
  • [P0] 카드 클릭 시 새 창으로 열기 (외부 사이트 링크)
  • [P1] 임베드 가능한 게임은 사이트 안에서 바로 실행(iframe)
  • [P1] 각 게임 카드에 "로그인 필요 여부", "광고 여부" 표시
  • [P2] 사이트 자체 제작 미니게임(낱말 맞추기, 카드 뒤집기 등)을 퀴즈 데이터로 자동 생성

게임 출처 예시 [확정 필요]: 교사가 만든 앱(구글 앱스·패들렛·클래스카드·워드월·띵커벨 등), 지자체/교육청 제공 앱. 실제 목록과 URL을 교사가 정리해 제공해야 한다.

4.5 교사용 페이지

  • [P1] 사이트 사용법, 수업 흐름 예시(40/45분 차시안)
  • [P1] 주제별 QR 코드 (인쇄용)
  • [P1] 전자칠판용 "발표 모드" (글자 크게, 메뉴 숨김)

4.6 콘텐츠 관리 (교사가 내용 수정하는 방법)

  • [P0] 모든 읽기 자료·퀴즈·게임 목록을 데이터 파일(JSON 또는 Markdown) 로 분리 → 코드를 몰라도 파일만 고쳐 반영
  • [P1] 대안: 구글 스프레드시트에 입력하면 사이트가 읽어오는 방식 (교사 협업에 유리)
  • [확정 필요] 위 두 방식 중 선택 (6장 참고)

6. 기술 요구사항

6.1 권장 구성 (기본안)

항목권장이유
사이트 형태정적 웹사이트 (HTML/CSS/JS 또는 Astro·Vite 등)서버·DB 불필요, 빠름, 무료
호스팅GitHub Pages / Netlify / Cloudflare Pages 중 택1무료, 학교망에서 접속 가능 여부 확인 필요
콘텐츠content/ 폴더의 JSON(또는 Markdown)교사가 직접 수정
저장브라우저 localStorage (레벨 선택, 완료 표시만)개인정보 미수집
로그인없음학생 계정 관리 부담 제거

6.2 대안 비교 [확정 필요]

방식장점단점
A. JSON 파일 + GitHub Pages (권장)안정적, 버전 관리, 무료수정 시 GitHub 사용법 약간 필요
B. 구글 스프레드시트 연동여러 교사가 엑셀처럼 공동 편집시트 공개 필요, 구조가 깨지면 사이트 오류
C. 노코드 도구(구글 사이트, 노션)제작 가장 쉬움퀴즈 자동 채점·수준 전환 등 기능 제약 큼

6.3 비기능 요구사항

  • 반응형: 360px(스마트폰) ~ 1920px(전자칠판)에서 가로 스크롤 없이 표시
  • 성능: 학교 와이파이에서 첫 화면 3초 이내, 이미지는 압축(WebP, 장당 200KB 이하 권장)
  • 접근성: 버튼 최소 44×44px, 글자 대비 4.5:1 이상, 이미지 대체 텍스트, 키보드 조작 가능
  • 가독성: 본문 기본 18px 이상(레벨 1은 20px), 줄 간격 1.7 이상
  • 브라우저: 크롬, 웨일, 사파리, 삼성 인터넷 최신 버전
  • 오프라인(P2): 한 번 연 자료는 인터넷이 끊겨도 보이도록(PWA)

8. 디자인 방향

  • 톤: 밝고 깔끔하게, 영광의 바다·갯벌·들판을 연상시키는 색(예: 바다 파랑, 갯벌 회갈색, 들판 초록)
  • 초등 저학년에 맞추되 중학생이 유치하게 느끼지 않도록 캐릭터 과다 사용 지양, 레벨 3은 더 차분한 화면
  • 레벨별 색상 구분(새싹·줄기·나무)으로 현재 수준을 항상 인지 가능하게
  • [확정 필요] 영광군 상징물/캐릭터 사용 여부 및 사용 허락

9. 저작권·개인정보·안전

  • 이미지·글 출처 표시 필수. 영광군청·문화재청 등 공공누리 자료는 유형(1~4유형) 확인 후 사용
  • 교재 원고 저작권 및 온라인 공개 범위 [확정 필요] (전체 공개 / 영광 지역 학교만 / 링크 아는 사람만)
  • 학생 이름·학번·점수 등 개인정보를 서버에 저장하지 않음
  • 외부 게임 링크는 등록 전 교사가 직접 확인: 광고·로그인 요구·부적절한 내용 여부
  • 외부 링크로 나갈 때 "다른 사이트로 이동합니다" 안내

12. 사전과제 체크리스트 (교사가 준비할 것)

제작 전에 아래를 준비하면 바로 시제품 제작이 가능하다.

  • 수준 체계 확정: 레벨 몇 단계? 이름은? (3.1)
  • 주제 목록: 교재 실제 목차 (3.2)
  • 시범 주제 1개 원고: 레벨별 읽기 자료 3편 (한글/워드 파일 그대로 OK)
  • 시범 주제 퀴즈: 레벨별 5문항 이상 + 정답 + 해설
  • 게임 목록: 게임 이름, 주소(URL), 관련 주제, 권장 레벨, 로그인 필요 여부 (엑셀 표 형태 권장)
  • 이미지: 사용할 사진과 출처
  • 공개 범위: 전체 공개 / 제한 공개 (9장)
  • 관리 방식: JSON 파일 vs 구글 스프레드시트 (6.2)
  • 사이트 이름·주소: 예) "영광 마을배움터" (예시)
  • 함께 관리할 교사: 수정 권한이 필요한 인원

13. 열린 질문

  1. 교재의 수준 구분이 3단계가 맞는가, 아니면 학년별(7단계)인가?
  2. 학생 퀴즈 결과를 교사가 확인해야 하는가? (필요하면 로그인 또는 구글 설문 연동 검토 → 범위가 크게 늘어남)
  3. 게임은 외부 링크 모음으로 충분한가, 자체 미니게임이 꼭 필요한가?
  4. 다른 지역 학교도 사용하는가? (공개 범위·저작권에 영향)
  5. 종이 교재와 페이지/차시 번호를 연결해야 하는가? (예: "교재 12쪽" 표시)
