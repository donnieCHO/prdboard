0.1 화면 문구 지침

  • 교사가 쓰는 말만 쓴다: 성취기준, 성취수준, 차시, 평가 요소, 문항, 발문, 작성 조건, 채점 요소, 척도, 채점 기준표. 「루브릭」「프롬프트」「토큰」「API」는 화면에 쓰지 않는다(용어는 GLOSSARY.md가 정본).
  • 척도는 「잘함·보통·도움 필요」. 점수(상3·중2·하1)로 바꾸지 않는다.
  • AI가 쓴 것은 늘 「제안」이라고 부르고, 교사가 「확인」하거나 「받기」를 눌러야 결과에 오른다.
  • 막힐 때는 무엇을 하면 되는지 한 문장으로 말한다(예: 「승인을 기다리는 중입니다. 관리자가 승인하면 바로 쓸 수 있습니다.」).

1. 문제 정의와 교육적 근거

1.1 해결하려는 문제

  • 서·논술형 평가지를 만들려면 성취기준 → 수업 활동 → 평가 요소 → 문항 → 채점 기준을 교사 혼자 이어야 해서 오래 걸린다.
  • 이전 판(0.2.0)은 이 흐름을 갖췄지만 Python 설치·터미널·OpenAI 키가 필요해 교사가 쓸 수 없었다.
  • 입구가 셋(로컬 예시·새 단원 AI·상세 편집)으로 갈라져 무엇을 눌러야 할지 몰랐다.
  • 채점은 종이에 따로 하고, 성취수준 판단 근거와 수준별 피드백이 남지 않는다.

1.2 교수·평가 가설

  • 문항이 실제 수업에서 학생이 한 일(수업 활동)과 예상 오개념에서 나오면, 채점 기준이 「답안에서 관찰할 수 있는 근거」가 된다.
  • 문항 하나가 성취기준 하나·평가 요소 하나에만 닿으면(ADR-0006), 채점 결과를 어느 성취기준의 A·B·C로 판단하는지 흐려지지 않는다.
  • 국가 성취수준 A·B·C 원문을 처음부터 옆에 두면, 채점 기준과 성취수준 종합판단 기준이 국가 기준에서 벗어나지 않는다.
  • 교사가 처음부터 쓰는 것보다 써 준 것을 고치는 편이 빠르고, 교사의 판단은 「확인」 단계에 모인다.

1.3 제품 원칙(우선순위 순)

  1. 교사가 정한다. AI는 제안만 한다. 문항은 교사가 확인해야 내보내지고, 척도와 성취수준은 교사가 눌러야 채점에 오른다(ADR-0007).
  2. 학생 정보는 서버에 남지 않는다. 평가지·평가 후 기록은 교사 기기에만 둔다(ADR-0002).
  3. 원문 그대로. 성취기준과 성취수준은 교육부 고시·국가 판본 원문만 쓴다(ADR-0004).
  4. 입구는 하나. 고르기 → 고치기 → 확인 → 내려받기. 상세 편집 화면과 처음부터 쓰는 입력칸은 없다.
  5. 엔진이 규칙을 검사한다. AI가 쓴 것은 엔진 규칙을 통과해야 화면에 오르고, 어기면 다시 쓴다.

2. 사용자

초등 교사. 구글 계정이 있고, 화면에서 고르기만 하기를 원하며, 긴 글을 직접 쓰기보다 써 준 것을 보고 고치는 편을 좋아한다.

3.2 이번 범위에서 제외

  • 평가지나 학생 기록을 서버에 저장하기, 「지난 평가지 다시 보기」(ADR-0002를 먼저 뒤집어야 함)
  • 교사가 자기 API 키를 넣는 방식
  • 상세 편집 화면, 여러 갈래의 입구, 처음부터 직접 쓰는 입력칸
  • 한 문항에 평가 요소·성취기준 여럿, 한 평가지에 성취기준 넷 이상
  • 원틱의 단원 색인·계정·데이터 연동(성취기준 611개 원문만 가져옴)
  • 시·도 교육청 판본 성취수준
  • AI가 성취수준까지 정하는 채점
  • 척도를 상(3)·중(2)·하(1) 점수로 바꾸는 선택
  • 플러그인 완성, ChatGPT 0.2.0 등록 수정

4.2 평가지 한 장의 데이터

  • 성취기준 1~3개, 문항 수, 평가 시간
  • 차시: 목표, 수업 활동, 예상 오개념, 평가 요소
  • 문항(평가 요소마다 하나): 발문, 제시 자료(없을 수 있음), 작성 조건, 채점 요소, 채점 요소별 잘함·보통·도움 필요 수행 특성, 예시 답안, 채점 시 유의 사항, 수준별 피드백, 확인 여부
  • 평가지 전체: 평가 과제, 성취수준 종합판단 기준

4.3 엔진 규칙(콘텐츠 검증 기준)

  • 문항 하나 = 성취기준 하나 + 평가 요소 하나
  • 작성 조건과 채점 요소는 짝을 이룬다
  • 채점 기준은 발문에 없는 것을 보지 않는다(「잘함은 작성 조건 범위 안에서」)
  • 제시 자료가 없으면 표·그림을 가리키지 않는다
  • 평가 요소는 서로 다른 수행이어야 한다
  • 성취수준 종합판단 기준은 척도를 단순 합산하지 않는다
  • 엔진 검사를 어기면 AI가 다시 쓰고, 이어서 AI 「문항 점검」이 학생처럼 풀어 보며 문제를 찾는다

  • 한 화면에 한 가지 일. 다음으로 넘어가는 버튼은 하나.
  • AI가 일하는 동안(1~1.5분) 무엇을 하고 있는지 보여 준다.
  • 학생용 평가지에는 채점 기준과 예시 답안이 없다.
  • PDF는 A4 인쇄 기준.

6. 기능 요구사항

FR-01. 구글 로그인·가입 승인 [P0]

  • 교사는 구글 계정으로 로그인한다(Supabase Auth, 구글만 켬).
  • 처음 로그인한 교사는 「승인 대기」로 오르고, AI 기능은 403과 대기 안내를 받는다.
  • 관리자는 「가입 승인」 칸에서 승인·막기를 한다. 막힌 교사는 「막혀 있습니다」 안내를 받는다.
  • 관리자는 구글이 확인한 이메일이 관리자 주소와 같을 때만 관리자로 본다(이메일 가입 등 다른 방법으로 관리자 주소를 사칭하지 못함).
  • 승인 대기·막힘이어도 견본 보기와 파일 열기는 된다.

FR-02. 하루 사용 상한 [P0]

종류교사 한 명서비스 전체
평가지(문항 쓰기 한 번)10100
차시 제안30300
답안 읽기(학생 한 명)30500
  • 하루는 한국 시각 자정에 바뀐다. AI가 실패한 호출은 세지 않고 되돌린다.
  • 상한은 환경변수로 바꾼다. 넘으면 429와 안내.

FR-03. 성취기준 고르기 [P0]

  • 학년군 → 교과 → 영역 → 성취기준(1~3개) → 문항 수·평가 시간.
  • 고른 성취기준의 국가 성취수준 A·B·C를 원문 그대로 보여 준다.

FR-04. 차시 제안 [P0]

  • AI가 성취기준에 맞는 차시의 목표·수업 활동·예상 오개념·평가 요소를 제안한다. 교사가 고친다.

FR-05. 문항 쓰기와 엔진 검사 [P0]

  • 평가 요소마다 문항 하나, 채점 기준, 예시 답안, 채점 시 유의 사항, 수준별 피드백. 평가지 전체의 평가 과제와 성취수준 종합판단 기준.
  • 엔진 규칙(4.3)을 어기면 AI가 다시 쓴다. 이어서 「문항 점검」이 학생처럼 풀어 보며 문제를 표시한다.

FR-06. 문항 확인 [P0]

  • 교사가 문항마다 「확인」. 고친 문항은 확인이 풀린다. 모든 문항이 확인되어야 내보내기가 열린다.

FR-07. 내려받기 [P0]

  • 학생용 평가지, 교사용 평가지, 채점 기준표(전남 예시자료집 양식)를 HTML·PDF로.
  • 평가지 파일(JSON) 저장·열기. 서버는 평가지를 돌려준 뒤 버린다.

FR-08. 견본 [P0]

  • 로그인 없이 견본 두 장을 열어 보고 내려받는다.

FR-09. 채점하기(직접 누르기) [P0]

  • 확인을 마친 평가지에서 「채점하기」. 명단은 한 줄에 한 명(번호만 써도 됨).
  • 학생마다 채점 요소별 척도를 누르면 엔진이 성취수준을 제안하고, 교사가 A·B·C를 정한다. 문항마다 수준별 피드백이 붙고, 교사가 관찰 근거를 적는다.
  • 평가 후 기록을 HTML로 내려받고, 채점 파일(JSON)로 저장했다가 이어서 한다.
  • 모든 일이 브라우저 안에서만 일어난다. 학생 이름과 채점 결과는 서버로 가지 않는다.

FR-10. 답안 읽기(AI 제안) [P0]

  • 반 전체를 번호순으로 스캔한 PDF 하나를 고르고 학생 한 명 쪽수(1~4)를 정한다.
  • 브라우저가 PDF를 쪽 그림(JPEG, 긴 변 2000px)으로 바꿔 학생 한 명씩 보낸다. PDF 파일·명단은 보내지 않는다.
  • AI가 답안을 옮겨 적고 채점 요소마다 척도와 근거 구절을 제안한다(정하지 못함 포함).
  • 교사가 「AI 제안 모두 받기」나 척도를 직접 눌러야 채점에 오른다. 받기 전에는 성취수준 제안·기록에 들어가지 않는다.
  • 동시에 3명씩 읽는다. 401·429·503이면 남은 학생을 멈추고, 못 읽은 학생만 다시 읽는다.
  • 서버는 그림과 읽은 글을 남기지 않는다(토큰 수만).

FR-11. MCP 입구 [P1]

  • 같은 엔진을 MCP 서버로 연다. 호스트 AI가 쓰고 엔진이 원문·규칙·검사·내보내기를 맡는다.
  • 교사가 확인했다고 말한 단위만 확인되고, 모두 확인되어야 내보낸다. 운영자 키·로그인·상한 없음.

FR-12. 평가지 전체 점검·규칙 층 [P1, 다음 판]

  • 요소 분포·중복·배점·분량 점검, 평가 방법별 규칙 층, 고친 뒤 연결 항목 재확인 표시. 비교 실험 결과(.scratch/engine-compare/)를 보고 정한다.

7. 상태 모델

7.1 교사 계정

(처음 로그인) → pending ──승인──► approved
                    └────막기──► blocked ──승인──► approved
관리자 주소 + 구글 확인 이메일 → 승인 없이 approved로 취급

7.2 문항

AI 작성 → 엔진 검사(어기면 다시 쓰기) → 점검 표시 → 미확인
미확인 ──「확인」──► 확인됨 ──고치기──► 미확인
모든 문항 확인됨 → 내보내기 열림

7.3 채점(학생 한 명, 채점 요소 하나)

비어 있음 ──직접 누름──────────────► 척도 정해짐
비어 있음 ──AI 읽기──► AI 제안(미반영) ──받기──► 척도 정해짐
                                   └──정하지 못함 → 교사가 누를 때까지 비어 있음
모든 채점 요소 정해짐 → 엔진이 성취수준 제안 → 교사가 A·B·C 결정

11. 개인정보와 학교 현장 운영 원칙

  • 학생 이름은 교사 브라우저 밖으로 나가지 않는다. 답안 그림은 명단과 순서로만 짝짓는다.
  • 스캔할 때 이름 칸을 가리고 번호만 보이게 하라고 안내한다. AI에게 개인 정보를 옮겨 적지 말라고 지시한다.
  • 답안 그림은 AI 회사로 나가지만 서버에 남지 않는다. 교사가 이 점을 알고 쓰도록 화면에 적는다.
  • 평가지·채점 파일은 교사 기기에만 있다. 잃어버리면 서버에서 되살릴 수 없다.

13. 수용 기준

  • 처음 로그인한 교사는 AI가 막히고 승인 대기 안내를 받는다. 견본은 열린다.
  • 관리자가 승인하면 그 교사가 바로 AI를 쓴다. 막으면 막혔다는 안내를 받는다.
  • 관리자 주소라도 구글이 확인한 이메일이 아니면 관리자가 아니다.
  • 하루 상한을 넘으면 429. AI 실패는 횟수에서 빠진다.
  • 확인 안 된 문항이 있으면 내보내기가 막힌다. 문항을 고치면 확인이 풀린다.
  • 학생용 평가지에 채점 기준·예시 답안이 없다.
  • 답안 읽기 제안은 받기 전에 성취수준·기록에 들어가지 않는다.
  • 서버 기록에 학생 이름·답안·평가지가 없다.
  • 위 항목은 tests/의 자동 시험으로 확인한다(132개 통과).

15. 결정이 필요한 항목

항목기본안
운영 열기 시점사용자가 「열자」 하면: 구글 앱 브랜딩 채우고 게시 → 대기 판 승격
다른 교사에게 열 때 AI 키확인함(2026-11-23): 요금제에 딸린 월 크레딧은 콘솔 조직의 API 키로 쓰며 「내 앱과 에이전트를 만드는 데」 쓰라고 안내됨 → 우리 서버가 우리 키로 교사들을 돕는 것은 허용되는 쓰임. 금지된 것은 요금제 로그인을 남의 앱에 넘기는 일. 크레딧이 다 떨어지면 요청이 멈춘다(청구 없음)
월 크레딧 소진하루 상한을 다 쓰면 약 40달러/일이라 200달러는 5일이면 끝난다. 열고 첫 달은 실제 사용량을 보고 전체 상한을 낮출지 정함
하루 상한쓰는 것을 보고 환경변수로 조정
척도 표기잘함·보통·도움 필요 유지, 점수 표기는 요청이 쌓이면
보완 규칙 반영비교 실험 결과로 정함(문항 문제 절반, 비용 +0.03달러)
「가상 학생 답안 채점 시험」을 기능으로 올릴지비교 실험 뒤
