PRD: 가정통신문 쉬운말·다국어 변환기 (가칭 "모두의 통신문")

항목내용
문서 버전v0.1 (초안)
작성일2026-11-25
작성자최현우 (부영여자고등학교)
제품 유형웹 앱 (교사용 편집 화면 + 학부모용 모바일 열람 페이지)
한 줄 소개공문체 가정통신문을 쉬운 한국어 요약 + 학부모 모국어 번역 + 다국어 회신으로 한 번에 바꿔 주는 도구

1. 배경 및 문제 정의

1.1 배경

  • 2026년 4월 기준 초·중·고 이주배경학생은 210,838명으로 전년보다 4.3% 늘었고, 전체 학생의 4.3%를 차지한다. (교육부·한국교육개발원, 2026 교육기본통계)
  • 이주배경학생 비율이 30%를 넘는 '밀집학교'는 2025년 기준 123개교이며, 한국어를 전혀 모르는 상태로 중도 입국하는 학생도 늘고 있다.
  • 2026년 4월 초·중등교육법 개정으로 '다문화 학생'이라는 용어가 '이주배경학생'으로 바뀌는 등, 이주배경학생 지원이 정책 과제가 되었다.

1.2 현장의 문제

대상문제
학부모가정통신문은 공문체·한자어(예: "기한 내 회신 요망", "수익자 부담", "결재 득")가 많아 한국어가 서툰 학부모는 이해하기 어렵다. 한국어가 모국어인 학부모도 긴 통신문에서 언제, 무엇을, 얼마나 해야 하는지만 빨리 찾고 싶어 한다.
학생통신문 내용을 자녀가 부모에게 통역하는 부담을 지고, 내용이 잘못 전달되는 경우가 생긴다.
교사번역기에 일일이 붙여 넣어 번역해야 하고, 번역 결과가 맞는지 확인할 방법이 없다. 회신이 늦거나 오지 않으면 개별 연락에 시간이 든다. 회신서에 학부모가 모국어로 쓴 질문은 읽을 수 없다.
일반 번역기의 한계날짜·금액·요일이 틀리게 번역되거나 빠질 수 있다. '방과후학교', '체험학습', '생활기록부' 같은 학교 용어가 직역되어 뜻이 통하지 않는다. 회신은 전혀 처리하지 못한다.

1.3 문제 정의 (한 문장)

교사가 가정통신문을 모든 학부모가 정확히 이해하고 바로 회신할 수 있는 형태로 바꾸는 데 시간이 너무 들고, 바꾼 결과가 정확한지 확인할 수도 없다.

2. 목표와 비목표

2.1 목표

  1. 원문을 업로드해서 학부모용 링크를 발행하기까지 3분 이내로 끝낸다.
  2. 교사는 언어를 고르지 않고 모든 학부모에게 같은 링크 하나를 보낸다. 언어는 학부모가 직접 고른다.
  3. 날짜·시간·금액·장소 같은 핵심 정보의 원문 일치율 100% (자동 검증)
  4. 학부모가 모국어로 읽고, 모국어로 회신하면 교사는 한국어로 받는다.
  5. 교사가 회신 현황을 한 화면에서 확인하고, 미회신자에게 다시 알릴 문구를 바로 만든다.

2.2 비목표 (이번 버전에서 하지 않음)

  • 학교 공식 알림 시스템(e알리미, 하이클래스 등)을 대체하지 않는다. 그 시스템에 링크를 붙여 쓰는 보조 도구로 둔다.
  • 실시간 통역(음성 통화)
  • 법적 효력이 있는 동의서의 전자서명 (번역본은 참고용, 원문 우선)
  • 나이스(NEIS) 연동

3. 사용자

3.1 주요 사용자

페르소나설명핵심 니즈
김 교사 (담임, 40대)반 학생 25명 중 이주배경 학생 3명. 매주 통신문 1~3건을 배포한다."빨리, 틀리지 않게, 회신까지 한 번에"
응우옌 씨 (학부모, 베트남 출신)한국 생활 10년. 일상 대화는 가능하지만 공문서 읽기는 어렵다."언제까지 뭘 내야 하는지 베트남어로 정확히"
이 씨 (학부모, 맞벌이)한국어가 모국어지만 긴 통신문을 끝까지 읽을 시간이 없다."핵심만 3줄로"

3.2 보조 사용자

  • 학년부장·기획 담당: 학년 공통 통신문을 한 번 변환해서 모든 반에 배포
  • 다문화(이주배경) 교육 담당 교사: 학교 용어집 관리

4. 핵심 사용자 시나리오

시나리오 A: 교사가 변환하고 발행

  1. 교사가 '현장체험학습 안내 및 참가 동의서' PDF를 올린다.
  2. AI가 핵심 정보 카드(일시, 장소, 비용, 준비물, 회신 마감, 회신 방법, 문의처)를 뽑아낸다.
  3. 쉬운 한국어 요약과 쉬운 본문이 만들어진다.
  4. 교사는 언어를 고르지 않는다. 시스템이 지원하는 모든 언어로 자동 번역한다.
  5. 언어별 자동 검증 결과가 한 표로 표시된다. 예: "✅ 10개 언어 날짜·금액·시간 모두 일치 / ⚠️ 베트남어 1문장 역번역 차이" 교사는 문제가 있는 언어만 한국어 역번역으로 확인한다.
  6. 교사가 검토하고 '발행'을 누르면 언어와 상관없는 링크 하나와 QR이 생성된다. 교사는 이 링크 하나를 모든 학부모에게 기존 알림 앱으로 똑같이 보낸다.

시나리오 B: 학부모가 열람하고 회신

  1. 학부모가 링크를 연다. 휴대폰(브라우저) 언어 설정에 맞는 언어가 자동으로 추천되고, 화면 맨 위의 언어 버튼으로 언제든 다른 언어로 바꿀 수 있다. 고른 언어는 그 기기에 기억되어 다음 통신문부터 바로 그 언어로 열린다.
  2. 맨 위에 핵심 정보 카드가 뜨고, 그 아래에 쉬운 본문이 나온다. '원문 보기'와 '듣기(TTS)' 버튼이 있다.
  3. 회신란에서 참가/불참을 고르고, 궁금한 점을 모국어로 적어 제출한다.
  4. 마감 하루 전 캘린더에 넣을 수 있도록 '일정 추가(.ics)' 버튼을 제공한다.

시나리오 C: 교사가 회신을 확인

  1. 대시보드에서 회신 18/25, 미회신 7명을 확인한다.
  2. 학부모가 베트남어로 쓴 질문 "버스비는 따로 내나요?"가 한국어로 번역되어 표시된다.
  3. 교사가 한국어로 답하면 학부모 언어로 번역되어 전달된다. (P1)
  4. '미회신 리마인드 문구 만들기'를 누르면 같은 링크가 들어간 짧은 안내 문구가 만들어진다. 학부모는 링크를 열어 자기 언어로 본다.

5.3 쉬운 한국어 변환

ID기능우선순위상세

F3-3어려운 낱말 풀이P1원문에 남겨야 하는 용어(예: '생활기록부')에 밑줄을 긋고, 누르면 풀이가 나옴

쉬운 말 작성 규칙 (프롬프트에 넣을 기준)

  • 한 문장에는 정보를 하나만 담는다. 문장은 짧게 쓴다.
  • 공문체 종결(~바랍니다, ~요망, ~하고자 함)을 평서형 존댓말(~해 주세요, ~합니다)로 바꾼다.
  • 한자어·행정 용어를 일상어로 바꾼다. 예: 수익자 부담 → 학부모님이 내는 비용 / 회신 → 답장 / 기한 → 마감일
  • 날짜에는 반드시 요일을 붙인다(예: 12월 3일(수)). 시간은 오전/오후를 명시한다.
  • 해야 할 일은 체크리스트로 쓴다.
  • 원문에 없는 내용은 덧붙이지 않는다. 핵심 정보 카드 값과 반드시 일치해야 한다.

7. 비기능 요구사항

7.1 개인정보·윤리

  • 최소 수집: 회신에는 학년·반·번호·학생 이름과 응답만 저장한다. 학부모 이름과 연락처는 받지 않는다.
  • 이주배경 정보 비노출: 교사가 "누가 어떤 언어를 쓰는지" 명단을 만들지 않도록, 언어는 학부모가 열람할 때 직접 고른다. 대시보드에서는 언어별 회신 수만 집계해서 보여 주고, 학생별 열람 언어는 표시하지 않는다. (회신 질문 번역에 필요한 원문 언어 정보만 내부에 보관)
  • LLM 전송 전 마스킹: 원문에 있는 개인정보(F1-5)를 가린 뒤에 외부 API로 보낸다.
  • 보관 기간: 회신 데이터는 통신문 마감 후 일정 기간(예: 학기 말)이 지나면 자동 삭제한다.
  • AI 생성 표기: 번역본·쉬운 말에는 AI가 만들고 교사가 검토했다는 표시를 붙인다.
  • 원문 우선 고지(F5-5)

7.2 접근성

  • 학부모 페이지 기본 글씨 18px 이상, 명도 대비 WCAG AA
  • 언어별 폰트 대응(베트남어 성조 기호, 키릴 문자, 크메르 문자 등)
  • 로그인 없이 링크만으로 열람·회신

7.3 성능·비용

  • 통신문 1건(A4 1~2쪽)을 지원 언어 전체로 변환하고 검증까지 마치는 데 60초 이내 (언어별 병렬 처리)
  • 학부모가 언어를 바꾸면 미리 만들어 둔 번역을 바로 보여 줌(1초 이내)
  • 번역 결과를 캐싱해서 같은 통신문을 다시 열 때 API를 호출하지 않음
  • 통신문 1건당 LLM 비용 목표: 수백 원 이하

8. AI 처리 설계

원문
 │  (1) 텍스트 추출 + 개인정보 마스킹 (규칙 기반)
 ▼
 │  (2) LLM: 구조화 카드 JSON 추출  ──▶ 교사 수정
 ▼
 │  (3) LLM: 쉬운 한국어 생성 (카드 값을 근거로)
 ▼
 │  (4) LLM: 언어별 번역 (쉬운 한국어 + 카드 + 용어집 입력)
 ▼
 │  (5) 검증
 │     ├ 규칙 기반: 숫자·날짜·금액 추출 후 대조
 │     └ LLM: 역번역 → 의미 일치 판정 (문장 단위)
 ▼
교사 검토 ─▶ 발행

설계 원칙

  • 구조화 우선: 날짜·금액처럼 틀리면 안 되는 정보는 JSON 카드의 값으로 고정한다. 번역할 때는 이 값을 그대로 끼워 넣는다(템플릿 치환). LLM이 숫자를 새로 쓰지 않게 한다.
  • 원문 → 쉬운 한국어 → 번역의 2단계: 공문체를 바로 번역하는 것보다 오역이 적고, 교사가 한국어 단계에서 내용을 확인할 수 있다.
  • 검증은 규칙 + LLM 이중: 숫자는 규칙으로, 의미는 LLM으로 확인한다.
  • 출력 형식 강제: 모든 LLM 응답은 JSON 스키마로 받는다.

구조화 카드 JSON 예시

  "type": "consent",

12. 위험과 대응

위험대응
오역으로 인한 피해(잘못된 날짜, 비용)구조화 값 고정 + 규칙 기반 숫자 검증 + 교사 최종 확인 + 원문 우선 고지
소수 언어 번역 품질 저하역번역 결과를 교사가 확인. 용어집으로 핵심 용어 고정. 학부모가 '번역 이상 신고' 버튼으로 피드백(P1)
개인정보 유출마스킹 후 API 전송, 최소 수집, 자동 삭제, 링크에 추측하기 어려운 ID 사용
이주배경 여부가 드러남언어는 학부모가 직접 선택, 학생별 언어 명단 미생성
링크가 외부로 퍼짐통신문 자체는 공개 정보 수준으로 작성. 회신은 학생 정보를 입력해야 가능. 마감 후 회신 폼 닫힘
LLM API 장애·비용결과 캐싱. 장애 시 원문과 이전 결과를 표시
