## 1. Firebase 준비 (약 15분, 처음 한 번)

1. [Firebase 콘솔](https://console.firebase.google.com)에서 **프로젝트 추가**. Google 애널리틱스는 꺼도 됩니다.
2. **빌드 > Firestore Database > 데이터베이스 만들기**
   - 위치: `asia-northeast3 (서울)` 권장. 나중에 바꿀 수 없습니다.
   - "프로덕션 모드"로 시작합니다.
3. **규칙** 탭에 `firestore.rules` 내용을 통째로 붙여 넣고 **게시**합니다.
   - CLI를 쓴다면: `.firebaserc`의 `YOUR_PROJECT`를 프로젝트 ID로 바꾸고 `firebase deploy --only firestore:rules`
4. **빌드 > Authentication > 시작하기 > 로그인 방법**에서 두 가지를 켭니다.
   - **익명**: 방문자용 (좋아요, 덧글, 팀 신청)
   - **Google**: 관리자용
5. **Authentication > 설정 > 승인된 도메인**에 GitHub Pages 도메인을 추가합니다. 예: `아이디.github.io`
6. **프로젝트 설정(톱니바퀴) > 내 앱 > 웹 앱 추가(</>)**. 표시되는 `firebaseConfig` 값을 `js/firebase-config.js`에 붙여 넣습니다.
   - 이 값은 공개되어도 괜찮습니다. 데이터 보호는 보안 규칙이 맡습니다.
   - 설정값을 넣지 않으면 사이트는 원문만 보이는 읽기 전용으로 열립니다.

## 2. GitHub Pages 배포 (처음 한 번)

1. GitHub에서 새 저장소를 만듭니다. 무료 계정은 **공개(Public)** 저장소여야 Pages를 쓸 수 있습니다.
   - 원문이 함께 공개되므로 작성자 선생님들의 동의를 먼저 받습니다.
   - 모든 페이지에 검색엔진 노출 막기(`noindex`)를 넣어 두었습니다.
2. 이 폴더의 **내용 전체**(숨김 파일 `.nojekyll` 포함)를 저장소 맨 위에 올립니다.
   - 웹에서 올릴 때: 저장소 화면 > Add file > Upload files에 폴더 안 파일들을 끌어다 놓기
   - 숨김 파일이 안 보이면 저장소에서 Add file > Create new file로 `.nojekyll`(내용 없음)을 만듭니다.
3. 저장소 **Settings > Pages > Build and deployment**: Source `Deploy from a branch`, 브랜치 `main` / `/(root)` 저장.
4. 1~2분 뒤 `https://아이디.github.io/저장소이름/` 주소가 열립니다.

## 3. 관리자 등록과 초기 데이터 (처음 한 번)

1. `https://…/admin.html`에 들어가 **Google로 로그인**합니다.
2. "관리자로 등록되어 있지 않습니다"와 함께 긴 ID가 보이면 복사합니다.
3. Firebase 콘솔 **Firestore > 데이터**에서 컬렉션 `admins`를 만들고, 문서 ID에 복사한 ID를 넣습니다. 필드는 `email`(문자열) 하나면 됩니다.
4. 관리자 화면을 새로고침하고 **「초기 데이터 만들기·갱신」**을 누릅니다. 이제 제출함에서 팀 만들기가 열립니다.

## 4. 새 PRD가 추가되었을 때

1. 드라이브에 새 PRD가 올라오면, 작업 폴더(PRD 원본이 있는 폴더)에 파일을 넣고 사이트 파일을 다시 만듭니다. 이 과정은 Claude에게 "PRD가 추가되었으니 반영해 줘"라고 요청하면 됩니다.
2. 새로 만든 파일 중 **바뀐 것만** GitHub 저장소에 다시 올립니다. 보통 `data/prds.js`, 새 `docs/prdNN.html`, `README.md`입니다.
   - `js/firebase-config.js`는 덮어쓰지 않도록 주의합니다. 덮어썼다면 설정값을 다시 넣습니다.
3. 관리자 화면에서 **「초기 데이터 만들기·갱신」**을 한 번 더 누릅니다. 새 PRD만 추가되고, 기존 PRD의 팀·비밀번호·덧글은 그대로입니다.

## 5. 작성자 선생님께 안내할 내용

- 자기 PRD의 원문 화면 > **팀** 탭 > 「이 PRD를 쓰신 선생님이신가요?」에서 비밀번호를 정합니다. 영문과 숫자를 섞어 6자 이상, 평소 쓰는 비밀번호는 쓰지 않습니다.
- 「팀 만들기 활성화」를 누르면 다른 선생님들이 「팀으로 참여하기」로 신청할 수 있습니다.
- 신청자 중 **최대 2명**을 선정하고(작성자 포함 3명) 「팀 확정」을 누릅니다.
- 다른 기기에서는 「작성자이신가요?」에 같은 비밀번호를 넣습니다.
- 비밀번호를 잊으면 운영진이 관리자 화면에서 **임시 비밀번호**를 발급합니다.

## 6. 첫 시험 순서 (배포 직후 권장)

1. 일반 창에서 좋아요, 덧글, 답글, 덧글 수정·삭제
2. 작성자로 비밀번호 설정 → 팀 만들기 활성화
3. 시크릿 창(다른 방문자)에서 팀으로 참여하기 신청 2~3건
4. 작성자 창에서 2명 선정 → 3명째 선정이 막히는지 → 팀 확정
5. 시크릿 창에서 틀린 비밀번호로 작성자 확인이 거절되는지
6. 관리자 화면에서 임시 비밀번호 발급 → 작성자 창의 작성자 확인이 풀리는지

## 7. 내 컴퓨터에서 미리 보기

모듈 스크립트와 원문 파일 불러오기를 쓰므로, 파일을 더블클릭해서는 열리지 않습니다. 이 폴더에서 간이 서버를 띄운 뒤 `http://localhost:8000`을 엽니다.

```
python -m http.server 8000
```

## 8. 운영 메모

- Firestore 무료 한도: 하루 읽기 5만 건, 쓰기 2만 건(2026-11-25 공식 안내 기준, 변경 가능). 넘으면 그날만 멈추고 요금은 청구되지 않습니다.
- 같은 브라우저에서 관리자로 로그인하면, 그 브라우저의 방문자 기록(좋아요 상태)이 새로 시작됩니다.
- 브라우저 데이터를 지우면 좋아요를 다시 누를 수 있고, 작성자 확인도 다시 해야 합니다.
- 서버가 없어 비밀번호 입력 횟수를 제한할 수 없습니다. 관리자 화면의 "설정" 칸(시각, 기기 ID)을 가끔 확인합니다.
- 설계 근거는 상위 폴더의 `firebase_db_design.md`에 있습니다. 규칙은 이 폴더의 `firestore.rules`가 정본입니다.
